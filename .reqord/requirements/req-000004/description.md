# グループ管理機能

## 概要

登録項目をグループ分けし、一覧の管理・絞り込みをしやすくする機能。

## 前提（要確認事項）

1項目が所属できるグループは**1つ**とする（複数グループ所属は初期スコープ外）。
グループの階層化（親子グループ）も初期スコープ外とする。この前提が実際の要望と異なる場合、
本要件を見直すこと。

## EARS形式要件

When ユーザーがグループを作成し、登録項目にグループを割り当てたとき,
the system shall 項目をグループ単位で分類し、一覧をグループごとに表示・絞り込み可能にする,
グループ名の編集・削除、および項目のグループ変更が随時可能な状態を維持する。

## 詳細要件

- グループは名前(1〜30文字)のみを持つ分類単位とする（説明文・アイコンの付加情報は持たない）。
- 1項目が所属するグループは1つ（未所属も許容し「未分類」として扱う）。
- 一覧画面でグループ単位の絞り込み表示ができる。
- グループの作成・名称編集・削除ができる。グループ削除時、所属項目は「未分類」に戻す（項目自体は削除しない）。

## ユースケース

1. ユーザーが新規グループを作成し、名前を入力する。
2. [[req-000001]] で登録済みの項目、または新規登録時に、所属グループを選択する。
3. 一覧画面でグループを選択すると、そのグループに属する項目のみが表示される。
4. グループ名を編集、または不要になったグループを削除する。

## 技術的制約

- グループデータは chrome.storage.local に保存する（[[technical.yaml]]参照）。
- storage / popup / options 各モジュールでグループの読み書き・表示・管理UIを分担する（[[structure.yaml]]参照）。

## エッジケース

- グループ削除時、所属していた項目は「未分類」表示になり、データ自体は失われない。
- 同名グループの重複作成は許容する（識別はグループIDで行う）。
- グループを作成せずに利用する場合、全項目は「未分類」として一覧表示される。

## 成功基準

- グループは最大50個まで作成可能。
- グループ絞り込み操作から一覧の再描画までが300ms以内に完了する。
- グループ削除後、旧所属項目の100%が「未分類」として一覧に表示され、データ欠損は0件。
- グループ名は1〜30文字でバリデーションされ、範囲外入力は100%エラーとなる。
