# 拡張機能名・説明の多言語対応

## ユーザーストーリー

As a 英語環境のブラウザを使う一般ユーザー,
I want 拡張機能の名称と説明を自分のブラウザの言語で読みたい,
So that ストアやブラウザの拡張機能管理画面で、何をする拡張機能なのかを理解したうえでインストール・利用できる.

## 詳細

現状 `manifest.json` の `name`（`Quick Copy`）と `description`（`登録した定型文字列をワンクリックでコピーできる拡張機能`）は単一言語のハードコードであり、`default_locale` も設定されていない。そのため英語環境のブラウザでも、拡張機能管理画面やストア掲載情報に日本語の説明が表示される。

本要件では `manifest.json` に `default_locale` を設定し、`_locales/ja/messages.json` と `_locales/en/messages.json` を追加して、`name` と `description` を `__MSG_*__` 参照へ置き換える。これによりブラウザのUI言語に応じて拡張機能の名称と説明が切り替わる。

### サイドパネル内の言語切替（req-000015）との関係

本要件で扱う言語と、req-000015 で実装済みのサイドパネル内の言語切替は、決定される仕組みが異なる別のものとして扱う。

- 本要件の言語: ブラウザのUI言語によって決まる。拡張機能の名称と説明（ブラウザやストアが表示する領域）に適用される。
- req-000015 の言語: 利用者がサイドパネルのメニューで明示的に選ぶ。サイドパネル内の表示文字列に適用される。

既存の独自i18n実装（`src/i18n/`）を `chrome.i18n` へ移行することは行わない。`chrome.i18n.getMessage` が返す言語はブラウザのUI言語に固定され、実行中に切り替えられないため、移行すると req-000015 の「利用者が言語を選べる」という要件を満たせなくなる。したがって本要件では `_locales` を manifest のメタデータのためだけに用い、`src/i18n/` は変更しない。

### 対象外

- サイドパネル内の表示文字列（req-000015 で対応済み）
- Chrome Web Store Developer Dashboard 上の掲載情報（説明文・スクリーンショット）の入力。本要件は掲載情報を言語別に入力できる前提を整えるところまでを範囲とする。
- 日本語・英語以外の言語の追加

## 成功基準

- ブラウザのUI言語が英語の環境で `chrome://extensions` を開くと、拡張機能の名称と説明が英語で表示される。
- ブラウザのUI言語が日本語の環境で `chrome://extensions` を開くと、拡張機能の名称と説明が日本語で表示される。
- 日本語・英語以外のUI言語環境では、`default_locale` に従い日本語の名称と説明が表示される。
- 拡張機能を読み込んだときに `chrome://extensions` に表示される警告・エラーが0件である。
- サイドパネル内の言語切替の動作が変わらない。既存の自動テストが全件パスする（2026-09-10時点で10ファイル・209件）。
