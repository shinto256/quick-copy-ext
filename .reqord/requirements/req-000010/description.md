# グループナビゲーション改善機能

## 概要

グループを20個以上作成した運用で、目的のグループを探しにくく、よく使うグループを先頭に置けず、長いグループ名がタブ幅を占有するという3つの課題が発生している。タブバーによる1クリック切替を維持したうえで、タブバー末尾の「▾」から全グループパネルを開き、グループ名の絞り込み、ドラッグ&ドロップによる並び替え、名称変更、削除、追加をパネルに集約する。あわせてグループ名の上限を20文字に変更し、入力欄で上限を打ち止めにする。

## EARS形式要件

When ユーザーがタブバー末尾の「▾」を押したとき,
the system shall 未分類を含む全タブを縦リストで一覧表示する,
各行にグループ名と所属項目件数を表示し、グループが上限の50個ある場合もスクロールで全件を確認できるようにする。

When ユーザーがパネルの縦リストで行をドラッグして別の位置で離したとき,
the system shall タブの並び順を並び替え後の順序で永続化する,
並び替え結果をタブバーの表示順へ即時反映する。

When ユーザーがパネルの絞り込み入力にグループ名の一部を入力したとき,
the system shall 入力文字列を含むグループのみを縦リストに表示する,
大文字小文字を区別せず部分一致で絞り込む。

While グループ名による絞り込みが有効な間,
the system shall 並び替え操作を無効にする,
部分表示の状態で並び替えて全体の順序が壊れることを防ぐ。

When ユーザーがグループ名を入力するとき,
the system shall 20文字を超える入力を受け付けない,
保存操作を行う前に上限に達したことがわかるようにする。

While 選択モードが有効な間,
the system shall タブバー末尾の「▾」を操作不可にする,
選択操作中にグループ管理操作が割り込むことを防ぐ。

## 詳細要件

### 全グループパネル

- タブバー末尾に「▾」ボタンを固定表示し、グループ総数を併記する（例: `▾ 24`）。
- パネルは未分類を含む全タブを縦リストで表示する。各行はグループ名と所属項目件数を持つ。
- グループ名による絞り込み入力を備える。既存の項目検索([[req-000002]])と同じく大文字小文字を区別しない部分一致とする。
- 各行の三点リーダーから名称変更と削除を行う。未分類は名称変更・削除の対象外とし、三点リーダーを表示しない。
- パネル内に「グループを追加」の導線を持つ。
- グループ削除の確認ダイアログには、あわせて削除される所属項目の件数を表示する。

### 並び替え

- 並び替えはパネルの縦リスト内のドラッグ&ドロップのみで行う。上下移動ボタンや「先頭へ移動」ボタンは設けない。
- 未分類も並び替えの対象とする。
- 並び替えた順序がタブバーの表示順になる。
- 拡張機能の起動時に選択されるタブは、並び順の先頭のタブとする。
- ドラッグ中は移動先の行が退避するアニメーションを表示し、入れ替わりが視覚的にわかるようにする。
- ドラッグ中にポインタがリストの端に達した場合はリストを自動スクロールする。

### グループ名の文字数

- グループ名の上限を30文字から20文字に変更する。20文字はパネルの縦リスト1行に収まる文字数であり、パネルを開けば必ず全文が読めることを保証する値とする。
- 入力欄で上限に達したら入力を打ち止めにし、現在の文字数と上限を表示する。
- 既に保存されている20文字を超える名前は切り詰めない。表示は末尾省略とし、名称変更時のみ新しい上限を適用する。
- タブバーのタブは幅の上限を設けて末尾を省略表示する。省略された名前の全文はパネルの縦リストで確認できる。

### タブバーからの管理操作の撤去

- 従来タブ内の三点リーダーに置かれていた名称変更・削除は、パネル側へ移す。タブバーは切替専用にする。
- タブから三点リーダーが無くなることで、同じ幅に表示できるタブの数が増える。

## ユースケース

1. ユーザーがタブバー末尾の「▾」を押し、全グループの一覧を表示する。
2. 絞り込み入力にグループ名の一部を入力し、目的のグループを絞り込む。
3. 行を選択してそのグループへ切り替える。
4. よく使うグループの行をドラッグしてリストの先頭へ移動する。タブバーの並び順が追従する。
5. 次回の拡張機能起動時、先頭に移動したグループが最初に開く。

## 技術的制約

- タブの並び順の情報源を新しいストレージキー `tabOrder`（未分類のセンチネルとグループIDの配列）に一本化する。既存の `groups` 配列は集合として扱い、配列順は順序の情報として使わない。
- `tabOrder` は読み出しのたびに正規化する。存在しないIDの除去、未収録グループの末尾追加、未分類センチネルの補完、重複の除去を行い、グループの追加・削除時に整合が崩れても自己修復する。
- ドラッグ&ドロップは Pointer Events で実装する。HTML5 drag and drop API は、ドラッグ中の演出が制御できずタッチ操作にも対応しないため使用しない。
- 行の高さを固定し、挿入位置を移動量と行高から算術で求める。ポインタ移動ごとの矩形計測を避ける。
- 既存の項目並び替え([[req-000005]])は上下移動ボタンで実装されており、ドラッグ&ドロップは未実装である。本要件で追加する並び替え機構は、後から項目リストへ適用できるインターフェースとして切り出す。
- 選択モード中の操作制限は既存の方針([[req-000009]])を踏襲する。

## エッジケース

- 並び替えの永続化に失敗した場合は、エラーを表示したうえで保存済みの順序から再描画し、画面の表示と保存状態が食い違ったままにしない。
- 絞り込み中はドラッグを開始できない。
- ドラッグ中にポインタ操作が中断された場合は、並び替えを確定せず元の順序に戻す。
- グループが0個の場合、パネルには未分類の行と追加の導線のみが表示される。
- 選択中のタブに対応するグループが削除された場合は、並び順の先頭のタブへ切り替える。

## 成功基準

- グループが50個の状態でも、パネルを開いてから絞り込み入力で目的のグループを表示するまでの操作が3アクション以内で完了する。
- 並び順の最下部にあるグループを先頭へ移動する操作が1回のドラッグで完了し、その順序がタブバーの表示順に100%反映される。
- 並び替えた順序が拡張機能の再起動後も100%保持され、起動時に選択されるタブが並び順の先頭になる。
- グループ名の入力欄で21文字以上を入力できない。
- グループの追加・削除を行った後も、タブの重複表示および欠落が0件である。
- 絞り込みが有効な間、並び替え操作が100%無効になる。
