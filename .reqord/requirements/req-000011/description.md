# サイドパネルのキーボード操作対応

## 概要

グループナビゲーション改善([[req-000010]])で追加した全グループパネルは、縦リストの行が`<li>`要素でフォーカスを受け取れず、並び替えもドラッグ操作のみで実現されている。このためキーボードだけを使う利用者は、パネルからグループを切り替えることも、グループの並び順を変更することもできない。DADS準拠UIデザイン刷新([[req-000008]])のFR-016は「すべてのインタラクティブ要素にフォーカス表示を提供する」ことを求めており、押すとグループが切り替わる縦リストの行はこれを満たしていない。

あわせて、サイドパネル全面を覆うオーバーレイ(全グループパネル・項目登録フォーム)は、表示中に背後の要素へフォーカスが移動でき、閉じるためのキー操作も統一されていない。

Chrome Web Storeでの公開を予定しているため、マウスを使わない利用者が主要な操作を完了できる状態にする。

## EARS形式要件

When 利用者が全グループパネルの縦リストにフォーカスを移したとき,
the system shall 行をフォーカス可能な操作要素として扱う,
フォーカスされている行が視覚的にわかるようにし、決定キーでそのグループへ切り替えられるようにする。

When 利用者が縦リストの行をフォーカスした状態で並び替えのキー操作を行ったとき,
the system shall その行を1つ上または1つ下の位置へ移動して順序を永続化する,
移動後もその行にフォーカスを保ち、続けて移動できるようにする。

While サイドパネル全面を覆うオーバーレイが表示されている間,
the system shall フォーカスをオーバーレイ内の要素に限定する,
背後の要素へフォーカスが移動して操作対象が分からなくなることを防ぐ。

When 利用者がオーバーレイ表示中に取消キーを押したとき,
the system shall そのオーバーレイを閉じてフォーカスを開く操作を行った要素へ戻す,
閉じた後にどこを操作していたかが分かる状態にする。

## 詳細要件

### 全グループパネルの縦リスト

- 縦リストの各行をキーボードでフォーカスできるようにする。フォーカス表示は既存のDADSフォーカス表現([[req-000008]])をそのまま用い、独自の表現は追加しない。
- フォーカスした行で決定キーを押すとそのグループへ切り替わり、パネルが閉じる。ポインタでのタップと同じ結果になる。
- 行内の三点リーダー・入力欄は従来どおり個別にフォーカスできる。行のフォーカスと行内要素のフォーカスが競合しないようにする。

### キーボードによる並び替え

- 縦リストの行をフォーカスした状態で、1つ上・1つ下へ移動させるキー操作を提供する。移動のたびに順序を永続化する。
- 移動後もフォーカスは移動した行に残す。連続して押すことで離れた位置まで移動できる。
- グループ名で絞り込んでいる間、および行のインライン編集中は、キーボードによる並び替えも無効にする(ドラッグ操作と同じ条件)。
- 項目一覧の並び替えは既存の上下移動ボタン([[req-000005]])でキーボードから到達できているため、本要件では追加しない。

### オーバーレイのフォーカス管理

- サイドパネル全面を覆うオーバーレイ(全グループパネル・項目登録フォーム)の表示中は、フォーカスがオーバーレイ内を循環し、背後の要素へ移動しない。
- オーバーレイを開いた時点でフォーカスを取得していた要素を記憶し、閉じたときにその要素へフォーカスを戻す。
- 取消キーで閉じる挙動を両方のオーバーレイで揃える。ただし行のインライン編集中は編集の取消が優先され、オーバーレイは閉じない(既存の挙動を維持)。

## ユースケース

1. 利用者がキーボードでタブバー末尾のボタンへ移動し、決定キーで全グループパネルを開く。
2. 絞り込み入力にフォーカスが当たった状態から、キーボードで縦リストの行へ移動する。
3. フォーカスした行で並び替えのキー操作を繰り返し、よく使うグループを先頭まで移動させる。
4. 決定キーでそのグループへ切り替え、パネルが閉じてフォーカスが元の位置へ戻る。

## 技術的制約

- 並び替えの永続化は既存の`reorderTabs`をそのまま使う。[[req-000010]]で並び替え機構を「並び替え後の順序を受け取って保存する」境界に切り出しているため、キーボード操作の経路を追加しても永続化側の変更は不要。
- フォーカス表示は既存の`:focus-visible`のグローバル指定に任せ、要素をフォーカス可能にするだけで表現が揃う。
- 行をフォーカス可能にする際、ドラッグ操作の判定(押した位置からの移動距離で切替と並び替えを区別する)を壊さないようにする。

## エッジケース

- 先頭の行で「上へ移動」、末尾の行で「下へ移動」を行った場合は、順序を変更せず何も起こらない。
- 絞り込みの結果が0件のとき、縦リストにフォーカス可能な行は存在しない。
- 並び替えの永続化に失敗した場合は、既存の挙動([[req-000010]])どおりエラーを表示して保存済みの順序から再描画する。フォーカスは操作していた行の位置に戻す。
- オーバーレイを開いた要素が閉じるまでに再描画で失われている場合(グループ削除によって行が消えた場合)は、フォーカスをオーバーレイの起点となる要素へ戻す。

## 成功基準

- 全グループパネルの縦リストの100%の行がキーボードでフォーカスでき、フォーカス位置が視覚的に判別できる。
- キーボード操作のみで、任意のグループを並び順の先頭へ移動できる。
- キーボード操作のみで、パネルを開いてから任意のグループへ切り替えるまでを完了できる。
- 絞り込み中およびインライン編集中は、キーボードによる並び替えが100%無効になる。
- オーバーレイ表示中、フォーカスが背後の要素へ移動する事象が0件である。
- オーバーレイを閉じた後、フォーカスが開く操作を行った要素に戻る割合が100%である。
