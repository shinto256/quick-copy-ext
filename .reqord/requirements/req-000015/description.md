# サイドパネルの多言語対応

## 概要

サイドパネルのその他メニュー（右上の三点リーダー）に、既存の「テーマ」と同じ形式で「言語」の項目を追加する。選択できる言語は日本語・英語の2つで、初期状態は日本語とする。選択した言語はテーマと同様に保存され、拡張機能を開き直しても維持される。

現状、サイドパネルの表示文字列（項目登録フォームのラベル、タブ、全グループパネル、選択モード、確認ダイアログ、エラーメッセージを含む画面内の全文言）はすべて日本語のハードコードであり、切り替える仕組みがない。本要件でこれらを翻訳可能な形に置き換え、選択した言語に応じて表示する。

あわせて、実装調査で見つかった既存の不整合を修正する。項目登録フォームの保存時検証エラー（`src/sidepanel/sidepanel.js` の `showItemError(error.message)`）は、`ItemRepository` が投げる内部検証エラーの英語メッセージ（例: `name must be 1-50 characters`）をそのまま利用者に表示している。全グループパネルの同種のエラー（`src/sidepanel/groupPanel.js` の `validationMessage`）は既に日本語へ変換済みであり、項目登録フォーム側だけが取り残されている。本要件でこの表示も翻訳の対象に含め、日本語のときも英語のときも意味の通る文言にする。

## EARS形式要件

When 利用者がその他メニューを開いたとき,
the system shall テーマの下に言語の選択項目を表示する,
日本語・英語の2つから選べるようにし、現在選択中の言語を強調表示する。

When 利用者が言語の選択項目からいずれかを選んだとき,
the system shall 選択した言語を保存し画面全体の表示を選択した言語へ即座に切り替える,
サイドパネルを開き直すことなく表示が切り替わるようにする。

While 利用者が言語を一度も選択していない間,
the system shall 表示言語を日本語とする,
初期状態が日本語であることを保証する。

When 利用者が拡張機能を開いたとき,
the system shall 前回選択した言語で表示する,
選択した言語が再起動後も維持されるようにする。

## 詳細要件

- その他メニューの「言語」セクションは、既存の「テーマ」セクション（`THEME_OPTIONS`・`renderMoreMenu`）と同じ見た目・同じ操作感で実装する。ラベルと2つの選択ボタン（日本語・英語）を並べ、現在選択中の言語のボタンを強調表示する。
- サイドパネル内の表示文字列を、選択した言語に応じて出し分けられる形に置き換える。対象は次のとおり。
  - `src/sidepanel/sidepanel.html` の静的なラベル・プレースホルダー・`aria-label`・`title`（検索欄、マスク切替、項目追加ボタン、その他のメニューを開くボタン、選択ツールバー、項目登録フォームの各項目、空状態の文言）。
  - `src/sidepanel/sidepanel.js` が動的に生成する文字列（タブのラベル、項目カードの操作ラベル、その他メニューの項目、コピー完了・コピー失敗の表示、確認ダイアログの文言、エラーメッセージ）。
  - `src/sidepanel/groupPanel.js` が動的に生成する文字列（全グループパネルの見出し・絞り込みのプレースホルダー・行の操作ラベル・削除確認ダイアログ・検証エラーメッセージ）。
- 言語を切り替えた時点で開いている画面（タブ一覧、項目一覧、全グループパネル、選択ツールバー）の表示も、再描画によって新しい言語に切り替える。開いていたフォームやパネルの開閉状態、入力中の値は変更しない。
- 項目登録フォームの保存時検証エラーを、全グループパネルと同じ方針（検証エラーの種類に応じた文言への変換）で日本語・英語それぞれの文言に変換する。内部の検証エラーメッセージ（英語の識別用文字列）をそのまま画面に表示しない。
- 言語の選択肢・保存の仕組みは、既存のテーマ設定（`SettingsRepository.setTheme`）と対になる形で、`SettingsRepository` に言語設定の取得・保存を追加する。

## ユースケース

1. 利用者がその他メニューを開き、「言語」から「English」を選ぶ。
2. サイドパネル全体の表示が即座に英語に切り替わる。開いていたタブの選択状態や入力中のフォームの内容は保たれる。
3. 利用者がサイドパネルを閉じて再度開くと、英語表示のまま起動する。
4. 利用者が言語を「English」に切り替え、項目名を空のまま保存しようとすると、検証エラーが英語で表示される。

## 技術的制約

- 翻訳文字列の管理方法（辞書ファイルの構成、参照の仕組み）は計画・実装フェーズで具体化する。既存のコードは表示文字列を各所に直接埋め込んでいるため、置き換えの範囲は広い。
- `chrome.storage.local` の既存キー（`settings`）に言語設定を追加する形とし、新規ストレージキーは設けない。
- Chrome Web Store上の拡張機能名・説明文（`manifest.json` の `name` / `description`）は、Chromeが管理するブラウザの言語設定に紐づく別の仕組みであり、本要件の対象に含めない。本要件はサイドパネル内の表示のみを対象とする。

## エッジケース

- 保存されている言語設定の値が想定外（"ja" "en" "zh" のいずれでもない）だった場合は、日本語として扱う。
- 言語を切り替えた直後に、選択モード中や項目編集フォームを開いている最中であっても、選択状態や入力中の内容を失わない。
- 全グループパネルや項目登録フォームが開いた状態で言語を切り替えても、開閉状態は変わらない。

## 成功基準

- その他メニューに「言語」の選択項目が表示され、日本語・英語の2つから選べる。
- 言語を選択すると、サイドパネル内の表示文字列の100%が選択した言語に切り替わる。
- 言語設定を保存後、拡張機能を閉じて再度開いても選択した言語が維持される。
- 初期状態（言語を一度も選択していない状態）でサイドパネルを開くと、日本語で表示される。
- 項目登録フォームの検証エラーが、選択した言語で意味の通る文言で表示される（内部の英語識別文字列がそのまま表示される事象が0件になる）。
