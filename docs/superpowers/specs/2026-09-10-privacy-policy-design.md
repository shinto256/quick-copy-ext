# プライバシーポリシー 設計

作成日: 2026-09-10

## 背景と課題

本拡張をChrome Web Storeへ公開するため、審査に必要な項目を洗い出した結果、
プライバシーポリシーが未整備であることが判明した。

Chrome Web Storeは、ユーザーが入力したデータを扱う拡張機能に対して、
公開URLで参照できるプライバシーポリシーの提示と、Developer Dashboard上での
データ使用に関する開示を求める。

本拡張は外部通信を一切行わず、データはすべて端末内の `chrome.storage.local` に
保存される。しかし項目の値（`value`）にはユーザーが任意の文字列を入力でき、
英語住所などの個人情報が含まれうる。したがって「データを扱っていない」ではなく
「何を端末内のどこに保存し、どこにも送信していないか」を明示する必要がある。

## 採用する方針

リポジトリ直下に `PRIVACY.md` を置き、そのGitHub上のファイルURLを
Chrome Web Storeに登録するプライバシーポリシーURLとする。

- URL: `https://github.com/shinto256/quick-copy-ext/blob/main/PRIVACY.md`
- リポジトリは公開設定のため、追加のホスティング設定なしに公開URLとして機能する。

内容は保存項目を実装に基づいて具体的に列挙する構成を採る。
「収集していない」という宣言だけでは、実際に個人情報を保存する拡張機能として
説明が不足しているように見えるため、保存する項目を明示したうえで
端末内に留まることを示す。

### 検討した代替案と却下理由

- **GitHub Pagesで公開する案** — 見栄えは良いが、Pagesの有効化とHTMLの作成が
  必要になる。Markdownのファイル URL でも審査要件は満たせるため、初回提出時点では
  却下する。将来必要になった場合は `PRIVACY.md` を元にPages化できる。
- **「データを収集しません」の一文のみで済ませる案** — 記述量は最小だが、
  項目の値に個人情報が入りうる本拡張では説明不足と判断し却下。
- **GDPR/CCPAの法的根拠やデータ主体の権利を詳細に記述する案** — 収集も送信も
  行わない本拡張には過剰。記述が増えるほど実装との乖離が生じる余地も増えるため却下。

## 決定事項

| 項目 | 決定 |
| --- | --- |
| ファイルの置き場所 | リポジトリ直下 `PRIVACY.md` |
| 記載言語 | 日英併記。日本語セクションの後に同内容の英語セクションを置く |
| 文体 | 通常の日本語・英語（法的文書のため圧縮しない） |
| 問い合わせ先 | GitHub Issues のURLのみ。メールアドレスは記載しない |
| 最終更新日 | 本文冒頭に記載する。内容変更時に改定する |
| バージョン番号 | 付けない。最終更新日で管理する |

## 章立て

日本語セクションと英語セクションで同一の章立てを用いる。

1. **概要** — 拡張機能の目的と、開発者がデータを一切収集しない旨。
2. **保存されるデータ** — 実装に基づく全項目の列挙。
   - `items`: `id`（UUID）, `name`, `value`, `groupId`, `createdAt`, `updatedAt`
   - `groups`: グループのIDと名称
   - `tabOrder`: タブの並び順
   - `settings`: `maskEnabled`, `theme`, `language`, `selectedGroupId`

   `value` にはユーザーが任意の文字列を入力できるため、住所などの個人情報が
   含まれる場合があることを明記する。
3. **保存場所** — `chrome.storage.local` のみを使用し、データは端末内に留まる。
   `chrome.storage.sync` を使用していないため、Googleアカウント経由で
   他の端末へ同期されることはない。
4. **外部への送信と第三者提供** — いずれも行わない。ネットワーク通信を行う
   コードを含まず、解析・広告・トラッキングの仕組みも含まない。あわせて
   Chrome Web StoreのLimited Use要件に対応する3点（データを販売しない、
   単一用途と無関係な目的に使用または転送しない、信用度の判定や融資の目的に
   使用または転送しない）を明記する。
5. **権限の利用目的** — `storage` は登録データと設定の保存、`sidePanel` は
   UIの表示にのみ使用する。閲覧中のサイトへアクセスするホスト権限は要求しない。
6. **クリップボード** — コピー操作を行ったときにのみ、ユーザーが選んだ項目の
   値をクリップボードへ書き込む。クリップボードの読み取りは行わない。
7. **データの削除方法** — 拡張機能内で項目やグループを削除する方法と、
   拡張機能をアンインストールすると `chrome.storage.local` のデータが
   削除されることを記載する。
8. **ポリシーの変更** — 変更時は本ファイルと最終更新日を改定する旨。
9. **問い合わせ先** — GitHub IssuesのURL。

## 検証方法

`PRIVACY.md` の記述が実装と一致していることを、以下の対応で確認する。

- 保存キーの網羅性: `src/storage/` 配下の各リポジトリが使用するストレージキー
  （`itemRepository.js` の `items`、`groupRepository.js` の `groups` と `tabOrder`、
  `settingsRepository.js` の `settings`）がすべて章2に含まれていること。
- `settings` の項目: `src/storage/settingsRepository.js` の `DEFAULT_SETTINGS`
  のキーがすべて章2に含まれていること。
- 権限の一致: `manifest.json` の `permissions` が章5の記載と一致し、
  `host_permissions` が存在しないこと。
- 外部通信の不在: `src/` 配下に `fetch` / `XMLHttpRequest` / 外部スクリプトの
  読み込みが存在しないこと。

## スコープ外

以下はChrome Web Store提出に必要だが、本設計の対象外とする。

- Developer Dashboard上のデータ使用に関する開示フォームの記入
- ストア掲載情報（説明文、スクリーンショット、プロモーション用タイル画像）
- `manifest.json` の `default_locale` 設定とストア掲載情報の多言語化
- リリースバージョン（`0.1.0`）の見直し
- LICENSEファイルの追加
