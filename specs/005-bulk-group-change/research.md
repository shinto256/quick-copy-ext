# Phase 0 Research: 選択項目グループ一括変更・選択モード中の個別操作制限

## 1. グループ一括変更の永続化方式

**Decision**: `itemRepository.js`に`updateGroupMany(ids, groupId)`を追加する。選択された全項目の
`groupId`を1回の`chrome.storage.local`書き込み(`setItem`)でまとめて更新する。既存の`update(id, patch)`
のようにグループ変更時に配列末尾へ移動する処理(`groupChanged`時の`splice`+`push`)も、対象IDすべてに
対して同じ規則を適用する。

**Rationale**: 既存の一括削除機能([[req-000007]])が`removeMany(ids)`で1回の書き込みに集約している
のと同じ理由で、選択件数分`update(id, patch)`をループ呼び出しすると書き込み回数が増え、途中で失敗
した場合に一部の項目だけグループが変わる中間状態が生じうる。1回の書き込みに集約することで、
成功基準SC-003(選択項目の100%のグループ変更・未選択項目は0件)を単一トランザクション相当で保証する。

**Alternatives considered**:
- 既存`update(id, { groupId })`をループ呼び出し: 実装は簡単だが上記の理由で却下。専用関数を
  追加するコストは低い。

## 2. 選択モード中のコピー/三点リーダー無効化の実現手段

**Decision**: `sidepanel.js`のカード描画処理(`renderItem`相当)で、`selectionMode`が`true`の間は
コピーボタン・三点リーダーボタンに`disabled`属性を付与する。両ボタンの`click`イベントハンドラ自体は
既存のまま残し、`disabled`によりブラウザ標準の挙動としてクリックイベントが発火しないようにする。

**Rationale**: 既存コードはすでに「選択モード以外ではカード全体をクリックでコピー可能にする」
(`if (!selectionMode) { li.classList.add("copyable"); ... }`)という分岐を持っており、同じ
`selectionMode`フラグを使って両ボタンの`disabled`を切り替えるのは既存パターンとの一貫性が高い。
ボタンを非表示(`hidden`)にする案も検討したが、選択モード中もカードのレイアウト(アクション領域の
幅)を変えたくないため、`disabled`によるグレーアウト表示を採用する。

**Alternatives considered**:
- ボタンを`hidden`にする: レイアウト崩れ(選択モード切替時にカードの高さ・幅が変わる)を避けるため却下。
- `pointer-events: none`をCSSで指定: `disabled`属性はアクセシビリティ上も明確(スクリーンリーダーが
  非活性を認識できる)であり、キーボード操作(Tabフォーカス)からも除外されるため`disabled`を採用。

## 3. 選択モード開始時の既存メニューの自動クローズ

**Decision**: `startSelectionMode()`内で、既存の`openItemMenuId`(現在開いている個別メニューの
対象ID)を`null`にリセットしてから`renderList()`を呼ぶ。

**Rationale**: 既存のカード描画ロジックは`openItemMenuId === item.id`の場合にのみ個別メニュー
(編集・削除)を描画する。選択モード開始時にこの状態をリセットするだけで、Clarifications
(2026-09-02)で決定した「選択モード開始と同時に開いていた個別メニューを自動的に閉じる」挙動を
既存の状態変数の再利用のみで実現できる。新たな状態変数の追加は不要。

**Alternatives considered**: なし(既存の状態管理をそのまま利用できるため代替案の検討は不要)。

## 4. グループ変更の変更先選択UI

**Decision**: 選択ツールバー(`selection-toolbar`)に「グループ変更」ボタンを追加し、押下すると
既存の項目編集フォームのグループ選択(`<select>`、`populateGroupSelect`相当のロジックを再利用)と
「適用」「キャンセル」ボタンを持つ簡易ポップオーバーを表示する。「適用」時のみ`updateGroupMany`を
呼び出し、「キャンセル」時は選択状態を維持したままポップオーバーを閉じる。

**Rationale**: 既存の項目編集フォーム(`openItemForm`内の`populateGroupSelect`)がすでに「未分類」を
含むグループ一覧を`<select>`に描画するロジックを持っており、これを再利用することで新たなグループ
一覧取得・描画ロジックの重複を避けられる。確認ダイアログ(`window.confirm`)ではなく専用ポップオーバー
を選ぶのは、変更先グループの選択という追加入力が必要なため(単純なOK/キャンセルでは表現できない)。

**Alternatives considered**:
- `window.prompt`でグループ名を直接入力: 誤入力やグループ名の表記揺れ(既存仕様上、同名グループの
  重複作成は許容されるため名前による一意特定ができない)のため却下。
- ボタン押下と同時に即座に適用されるドロップダウン(選択=即確定): Acceptance Scenario(選択後に
  キャンセルできる)を満たせないため却下。「選択→適用/キャンセル」の2段階操作を採用する。
