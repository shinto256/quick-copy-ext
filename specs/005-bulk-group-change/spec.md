# Feature Specification: 選択項目グループ一括変更・選択モード中の個別操作制限

**Feature Branch**: `005-bulk-group-change`

**Created**: 2026-09-02

**Status**: Draft

**Reqord Requirements**: [[req-000009]] 選択項目グループ一括変更機能（承認済み・要約は下記「Reqord要件要約」参照）

**Input**: User description: "req-000009「選択項目グループ一括変更機能」に基づく仕様作成。概要: サイドパネルの一覧から複数項目を選択している際に、選択したすべての項目のグループをまとめて変更できる機能。あわせて、選択モード中は各カードの三点リーダー(個別メニュー)およびコピーボタンを操作不可にし、誤操作を防ぐ。"

## Reqord要件要約

- **req-000009（選択項目グループ一括変更機能）**: 一覧から複数項目を選択している際に、選択したすべての項目のグループをまとめて変更できる機能。あわせて、選択モードが有効な間は各カードの三点リーダー(個別メニュー)およびコピーボタンを操作不可にし、選択操作以外の誤操作を防ぐ。選択UI・選択状態リセットの方針は既存の一括削除機能([[req-000007]])を踏襲し、変更先グループの選択は既存のグループ管理機能([[req-000004]])を踏襲する。

本specは既存spec `003-sidepanel-list-enhancements` で実装済みの選択モード・一括削除機能を拡張し、(1)選択モード中の個別カード操作(三点リーダー・コピー)の無効化、(2)選択項目のグループ一括変更、の2点を追加する。既存の選択モード開始操作・チェックボックスUI・一括削除・選択状態リセットの挙動は変更しない。

## Clarifications

### Session 2026-09-02

- Q: 選択モードを開始する直前に、いずれかのカードの三点リーダーメニュー(編集・削除)がすでに開いていた場合、そのメニューはどうなるべきか？ → A: 選択モード開始と同時に、開いていた個別メニューは自動的に閉じる。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 選択モード中は個別カード操作を誤って行わない (Priority: P1)

利用者は、複数項目を選択している最中に、うっかり個別カードのコピーボタンや三点リーダーメニューを押してしまい、意図しないコピーや編集・削除が発生することを避けたい。

**Why this priority**: 現状、選択モード中でもカード本体のクリックコピーのみが無効化されており、コピーボタン・三点リーダーボタン自体は押せてしまう。選択操作中の誤操作事故を防ぐ土台となるため、グループ一括変更機能より優先度が高い。

**Independent Test**: 選択モードを開始した状態で、任意のカードのコピーボタンおよび三点リーダーボタンを押しても、コピーが実行されず、個別メニュー(編集・削除)も開かないことを確認する。

**Acceptance Scenarios**:

1. **Given** 選択モードが有効になっている、**When** 任意のカードのコピーボタンを押す、**Then** 値はコピーされず、コピー完了の表示(チェックマーク等)も行われない。
2. **Given** 選択モードが有効になっている、**When** 任意のカードの三点リーダーボタンを押す、**Then** 個別メニュー(編集・削除)は開かない。
3. **Given** 選択モード中に個別メニューが開いていない、**When** チェックボックスで項目を選択する、**Then** 選択操作自体は通常どおり行える(コピーボタン・三点リーダーボタンの無効化は選択操作を妨げない)。
4. **Given** 選択モードを終了(キャンセル/選択解除、または一括削除完了)する、**When** 通常表示に戻る、**Then** 各カードのコピーボタン・三点リーダーボタンは再び操作可能になる。
5. **Given** あるカードの個別メニュー(三点リーダーメニュー)が開いている、**When** 選択モードを開始する、**Then** 開いていた個別メニューは自動的に閉じる。

---

### User Story 2 - 選択した複数項目のグループをまとめて変更する (Priority: P2)

利用者は、複数の項目を選択し、それらのグループをまとめて変更したい。1件ずつ編集フォームを開いてグループを変更する手間を省きたい。

**Why this priority**: 既存の個別グループ変更(編集フォーム経由)を補完する効率化機能。個別操作の誤操作防止(User Story 1)ほど緊急性は高くないが、既存の一括削除と対をなす価値の高い機能。

**Independent Test**: 選択モードで複数項目を選択し、「選択項目のグループを変更」操作から変更先グループを選んで確定すると、選択したすべての項目のグループが変更され、一覧・グループ絞り込み表示に反映されることを確認する。

**Acceptance Scenarios**:

1. **Given** 選択モード中に複数項目を選択している、**When** 選択ツールバーの「グループ変更」操作を行う、**Then** 既存のグループ一覧(未分類を含む)から変更先グループを選べる選択UIが表示される。
2. **Given** グループ変更の選択UIで変更先グループを選び確定する、**When** 変更が実行される、**Then** 選択されていたすべての項目のグループが変更先グループに更新され、一覧・グループ絞り込み表示に即時反映される。
3. **Given** グループ一括変更が完了した直後、**When** 一覧を確認する、**Then** 選択していなかった項目のグループは変更されず、選択モードは終了し通常表示に戻る。
4. **Given** 選択件数が0件の状態、**When** 「グループ変更」操作を行おうとする、**Then** 操作は無効化されており実行できない(一括削除ボタンと同様の扱い)。
5. **Given** グループ変更の選択UIを開いている、**When** 変更を確定せずキャンセルする、**Then** 項目のグループは変更されず、選択状態も維持される(選択モードは終了しない)。

---

### Edge Cases

- 選択モード中に選択対象タブの項目が0件になった場合(既存仕様どおり選択モードは自動終了する)、グループ変更操作も対象を失い実行不可能になる。
- グループ一括変更の変更先として、選択項目の一部がすでに所属しているグループを選んだ場合でも、エラーにはせず全選択項目のグループを一律で変更先グループに揃える。
- グループ一括変更の対象グループが変更操作の直前に削除されていた場合(グループ一覧の再取得により選択肢から消えるため)、その選択肢は表示されず選択不可能である。
- 選択モード中に一覧が再描画される操作(タブ切替・検索)が発生した場合、既存仕様([[req-000007]])どおり選択状態・選択モードはリセットされ、グループ変更の選択UIも閉じる。
- 選択モードを開始した時点で、いずれかのカードの個別メニュー(三点リーダーメニュー)が開いていた場合、そのメニューは選択モード開始と同時に自動的に閉じる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、選択モードが有効な間、各カードのコピーボタンをクリックしても値をコピーしないようにしなければならない。
- **FR-002**: システムは、選択モードが有効な間、各カードの三点リーダーボタンをクリックしても個別メニュー(編集・削除)を開かないようにしなければならない。
- **FR-002a**: システムは、選択モードを開始した時点で開いていた個別メニューがあれば、自動的に閉じなければならない。
- **FR-003**: システムは、選択モードが有効な間もチェックボックスによる項目の選択・解除操作は妨げてはならない。
- **FR-004**: システムは、選択モードを終了した場合、各カードのコピーボタン・三点リーダーボタンの操作を通常どおり有効に戻さなければならない。
- **FR-005**: システムは、選択モード中に選択ツールバーへ「グループ変更」操作を提供しなければならない。選択件数が0件の場合はこの操作を無効化しなければならない。
- **FR-006**: システムは、「グループ変更」操作から、既存のグループ一覧(未分類を含む)を変更先として選択できるUIを提供しなければならない。
- **FR-007**: システムは、変更先グループが確定された場合、選択されていたすべての項目のグループを変更先グループに更新し、未選択項目のグループは変更してはならない。
- **FR-008**: システムは、グループ一括変更の確定後、一覧表示およびグループ絞り込み表示に変更結果を即時反映しなければならない。
- **FR-009**: システムは、グループ一括変更の確定後、選択モードを終了し選択状態をリセットしなければならない。
- **FR-010**: システムは、グループ変更の選択UIがキャンセルされた場合、項目のグループを変更せず、選択状態・選択モードを維持しなければならない。

### Key Entities

- **項目（Item）**: req-000001で定義済み。本specでは既存の`groupId`属性を、単体編集に加えて一括更新の対象として扱う（新規属性の追加はない）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 選択モード中、100%のカードでコピーボタン・三点リーダーボタンの操作が無効化される(押しても副作用が発生しない)。
- **SC-002**: グループ一括変更操作(変更先確定)から一覧表示への反映までが1秒以内に完了する。
- **SC-003**: グループ一括変更は、選択した項目の100%のグループを変更し、未選択項目のグループ変更は0件である。
- **SC-004**: 選択件数が0件の状態でグループ変更操作を行ってもエラーは発生せず、グループの変更も0件である。
- **SC-005**: 利用者は、N件の項目のグループ変更を、個別編集を繰り返す場合(N回の編集フォーム操作)より少ない操作回数(選択N件+グループ変更操作1回+変更先選択1回)で完了できる。

## Assumptions

- 「グループ変更」操作の配置は、既存の選択ツールバー(選択件数表示・一括削除ボタン・キャンセルボタンが並ぶ領域)に一括削除ボタンと並べて追加する。
- 変更先グループの選択UIの具体的な見た目(ドロップダウン選択か、簡易モーダルか)は計画・実装フェーズで具体化する。いずれの場合も「変更前に選択・確定でき、キャンセル可能」という要件は満たす。
- コピーボタン・三点リーダーボタンの無効化は、ボタン自体を非表示にするか、`disabled`状態にするかは計画・実装フェーズで具体化する。いずれの場合も「クリックしても副作用(コピー実行・メニュー表示)が発生しない」という要件は満たす。
- 既存spec `003-sidepanel-list-enhancements` で実装済みの選択モード開始操作・チェックボックスUI・一括削除・選択状態リセット(タブ切替/検索時)の挙動は変更しない。
