# Quickstart: グループナビゲーション改善の検証手順

## 前提

- Google Chrome（またはEdge）114以降。
- リポジトリを取得済み、`npm install` 実行済み。
- 本feature実装後の状態。`chrome://extensions` で拡張機能を読み込み・再読み込み済み。
- 検証用データとして**グループを20個以上**登録し、各グループに項目が数件ずつ登録されていること。
  グループ名には20文字に近い長い名前を1つ以上含めること。
- 上限まわりの確認には**グループ50個**の状態も用意すること（`chrome://extensions` の
  「Service Worker」コンソールから `chrome.storage.local` へ直接投入してもよい）。

---

## 1. 全グループパネルで探す（User Story 1 / SC-001, SC-007, SC-008）

1. タブバー末尾のボタンを確認する → 常に見える位置に固定され、**未分類を含むタブ総数**が併記されて
   いることを確認する（FR-001）。タブバーを横スクロールしてもボタンが隠れないこと。
2. そのボタンを押す → パネルが**サイドパネル全面を覆い**、背後の項目一覧が隠れることを確認する
   （FR-002a）。開くまでが体感1秒以内であること（SC-007）。
3. 縦リストに**未分類を含む全タブ**が並び、各行にグループ名と所属項目件数が表示されていることを
   確認する（FR-002 / FR-003）。
4. 20文字のグループ名の行を確認する → 末尾省略されず**全文が表示**されていることを確認する（SC-008）。
5. パネルを開いた直後にキーボードから文字を入力する → 絞り込み入力にフォーカスが当たっており、
   入力した文字がそのまま絞り込みに反映されることを確認する（FR-008a）。
6. グループ名の一部を入力する → 大文字小文字を区別せず部分一致で絞り込まれることを確認する（FR-004）。
   英字を含む名前で大文字・小文字を入れ替えても同じ結果になること。
7. 絞り込みに一致しない文字列を入力する → 行が0件になり、該当なしであることがわかる表示が出ることを
   確認する。
8. 絞り込んだ状態で目的の行を押す → そのグループへ切り替わり、パネルが閉じることを確認する（FR-005）。
   **パネルを開く→絞り込みを入力→行を押す の3アクションで到達できること**（SC-001）。
9. 再度パネルを開き、絞り込み入力が**空にリセットされている**ことを確認する。
10. `#group-panel-close` の閉じるボタンを押す → グループが切り替わらずパネルだけが閉じ、項目一覧が
    再び表示されることを確認する（FR-008）。
11. 再度パネルを開き、`Escape` キーを押す → 同様にグループが切り替わらず閉じることを確認する（FR-008）。
12. **グループ50個の状態**でパネルを開く → スクロールで全50件と未分類を確認できることを確認する（FR-006）。
13. **並び順の40番目あたりのグループを選択した状態**でパネルを開く → その行が表示範囲に入る位置まで
    スクロールされ、行が選択中として強調表示されていることを確認する（FR-008b）。
14. ヘッダーの「その他メニュー」から「選択」で選択モードに入る → タブバー末尾のボタンが無効化され、
    押してもパネルが開かないことを確認する（FR-007）。

## 2. ドラッグで並び替える（User Story 2 / SC-002, SC-003, SC-006, SC-009）

1. パネルを開き、縦リストの行を掴んで上下に動かす → 移動先の行が**退避して挿入位置が示される**ことを
   確認する（FR-014）。動きがカクつかず、掴んだ行が浮いて見えること。
2. 行を掴んだまま**リストの下端でポインタを止める** → リストが自動的にスクロールし続けることを
   確認する（FR-015）。上端でも同様に確認する。
3. **並び順の最下部にあるグループを1回のドラッグで先頭まで移動**する → 自動スクロールを使って
   1ドラッグで到達でき、離すと挿入位置に吸着することを確認する（SC-002）。
4. パネルを閉じてタブバーを確認する → タブの表示順が並び替え後の順序と一致していることを
   確認する（FR-012 / SC-002）。
5. **未分類の行**を掴んで別の位置へ移動する → 未分類も並び替えの対象として順序が変わり、タブバーにも
   反映されることを確認する（FR-010）。
6. 拡張機能のサイドパネルを閉じて開き直す → 並び替えた順序が保持されており、**並び順の先頭のタブが
   選択された状態**で開くことを確認する（FR-013 / SC-003）。
7. 絞り込み入力に文字列を入力した状態で行を掴んで動かす → **並び替えが始まらない**ことを確認する
   （FR-016 / SC-006）。このとき掴み手のアイコンが非表示になっていること。
8. 同じく絞り込み中に行を押して離す → **グループの切替は行える**ことを確認する（絞り込み中に無効化
   されるのは並び替えのみ）。
9. 行を押して**ほとんど動かさずに離す** → 並び替えは発生せず、そのグループへ切り替わることを
   確認する（FR-009a）。
10. 行を押して**5px以上動かしてから離す** → グループの切替は発生せず、並び替えが確定することを
    確認する（FR-009a）。切替と並び替えが同時に起きないこと。
11. 行の三点リーダーを押す → 並び替えもグループ切替も発生せず、名称変更・削除の操作が表示されることを
    確認する（FR-009b）。
12. 行を掴んだまま**他のウィンドウへ切り替える**などでドラッグを中断する → 並び替えが確定せず、
    元の順序に戻ることを確認する（FR-017）。
13. 保存失敗時の挙動（FR-018 / SC-009）は通常操作では再現できない。`chrome://extensions` の
    Service Worker コンソールから `chrome.storage.local.set` で `groups` を書き換えて
    `reorderTabs` の検証を失敗させ、エラー表示が出たうえで**保存済みの順序から再描画**されることを
    確認する。

## 3. グループ名の文字数（User Story 3 / SC-004, SC-008）

1. パネルを開き、行の三点リーダーから「名称を変更」を選ぶ → 行が入力欄に切り替わり、現在の名前が
   入った状態でフォーカスが当たっていることを確認する（FR-025）。
2. 入力欄と**同じ行に文字数表示**（`n / 20`）が出ていることを確認する（FR-022）。
3. **21文字以上を入力しようとする** → 20文字で入力が打ち止めになることを確認する（FR-021 / SC-004）。
   日本語（全角）と英数字（半角）の両方で確認する。
4. `Escape` を押す → 名前が変更されず行の表示に戻ることを確認する。このとき**パネルは閉じない**こと。
5. 名前を変更して `Enter` を押す → 変更が保存され、タブバーの表示にも反映されることを確認する。
6. **20文字を超える名前を持つグループを用意する**（上限変更前のデータを模して、Service Worker
   コンソールから `groups` に25文字程度の名前を直接投入する）。
7. パネルとタブバーを確認する → 名前が**切り詰められていない**ことを確認する（FR-023）。パネルの
   縦リストとタブでは末尾省略で表示され、`title` にマウスを乗せると全文が出ること（FR-024）。
8. その25文字のグループを「名称を変更」で開き、21文字を入力しようとする → 20文字で打ち止めになり、
   **変更時には新しい上限が適用される**ことを確認する（FR-023）。
9. タブバーを確認する → 長い名前のタブが幅の上限内で末尾省略され、他のタブを押しつぶしていないことを
   確認する（FR-024）。

## 4. 管理操作のパネル集約（User Story 4 / SC-005）

1. タブバーの各タブを確認する → **タブ内に三点リーダーが表示されていない**こと、タブを押すと
   切り替えのみが起きることを確認する（FR-029）。タブバー末尾の `＋` ボタンも無くなっていること。
2. パネルを開き、**未分類の行**を確認する → 三点リーダーが表示されず、名称変更・削除が行えないことを
   確認する（FR-026）。
3. 実グループの行の三点リーダーから「削除」を選ぶ → 確認ダイアログに**あわせて削除される所属項目の
   件数**が含まれていることを確認する（FR-027）。
4. 確認をキャンセルする → グループも項目も削除されないことを確認する。
5. **現在選択中のグループ**を削除する → 並び順の先頭のタブが選択された状態になることを
   確認する（FR-030）。
6. `#group-panel-add` の「グループを追加」を押す → 縦リストの**末尾に入力用の行**が挿入されて
   フォーカスが当たることを確認する（FR-028）。
7. 名前を入力して `Enter` を押す → グループが作成され、**並び順の末尾**に現れることを
   確認する（FR-019）。タブバーの末尾にも追加されていること。
8. 再度「グループを追加」を押し、`Escape` を押す → 入力行が取り除かれ、グループが作成されないことを
   確認する。
9. インライン編集中（名称変更中、または入力行が表示中）に他の行を掴んで動かす → **並び替えが
   始まらない**ことを確認する（FR-025a）。
10. 名前を空のまま `Enter` を押す → 検証エラーが表示され、保存されないことを確認する。
11. **グループ50個の状態**で「グループを追加」を実行する → 上限のエラーが表示され、作成されないことを
    確認する。
12. **自己収束の確認（SC-005）**: グループの追加と削除を10回程度繰り返す → タブバーとパネルの縦リストで
    **タブの重複表示および欠落が0件**であることを確認する。
13. さらに Service Worker コンソールから `chrome.storage.local.set({ tabOrder: [...] })` で
    「実在しないIDを含む」「重複を含む」「`__unassigned__` を欠く」「グループが未収録」の各パターンを
    投入し、サイドパネルを開き直す → いずれの場合もタブが重複・欠落なく表示されることを
    確認する（FR-019）。

## 5. 既存機能の回帰確認

1. 項目の登録・編集・削除がこれまでどおり行えること。
2. カードのワンクリックコピーとマスク表示の切替が動作すること。
3. 項目名検索でタブ内の項目が絞り込めること。
4. 項目の `▲▼` による並び替えが動作すること（セクション6でドラッグ操作を追加したが、`▲▼` は
   代替手段として維持している）。
5. 選択モードによる一括削除・一括グループ変更が動作すること。項目編集フォームのグループ選択に
   全グループが並ぶこと。
6. テーマの自動追従とライト/ダークの手動固定が動作すること。

## 6. 項目一覧のドラッグ&ドロップ（spec 003 FR-001 の未実装分の解消）

本featureで作った `dragReorder` を項目一覧にも適用したため、あわせて確認する。
手順は [specs/003-sidepanel-list-enhancements/quickstart.md](../003-sidepanel-list-enhancements/quickstart.md)
のセクション1「並び替えを確認」を実行する。特に以下を見る。

1. 値の長さが異なるカード（1行のものと複数行になるもの）を混ぜた状態で並び替える → 退避と吸着が
   ずれないことを確認する（項目カードは高さが可変なため）。
2. カードを押してほとんど動かさずに離す → 並び替えではなくコピーが実行されることを確認する。
3. 一覧が画面に収まらない状態で、カードを掴んだままウィンドウの上端・下端へ寄せる →
   サイドパネル全体がスクロールすることを確認する（項目一覧は `#item-list` ではなく
   ドキュメントがスクロールする）。
4. 検索絞り込み中・選択モード中は並び替えが始まらないことを確認する。
5. `▲▼` による並び替えが従来どおり動くことを確認する。

## 7. 自動テストの実行

```bash
npm test
```

- 既存テストがすべてパスすること（回帰なし）。特に `itemFilter.test.js` は `UNASSIGNED_TAB_ID` の
  定義位置を移して再エクスポートに変えたあとも、import 経路を変更せずにパスすること。
- 新規: `tests/unit/tabOrder.test.js` の `normalizeTabOrder` / `isValidTabOrder` のテスト
  （[contracts/tab-order-contract.md](./contracts/tab-order-contract.md) 参照）がパスすること。
- 追加: `tests/unit/groupRepository.test.js` の `listTabOrder` / `reorderTabs` / `NAME_MAX_LENGTH` /
  `remove` のテスト（[contracts/group-repository-additions.md](./contracts/group-repository-additions.md)
  参照）がパスすること。

`src/sidepanel/dragReorder.js` と `src/sidepanel/groupPanel.js` はDOM操作が中心のため、既存specと
同方針でユニットテスト対象外とし、上記1〜6の手動検証で担保する。
