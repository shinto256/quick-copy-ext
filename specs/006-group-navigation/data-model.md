# Phase 1: Data Model — グループナビゲーション改善

**Feature**: `006-group-navigation` | **Date**: 2026-09-04 | **Spec**: [spec.md](./spec.md)

`chrome.storage.local` に保存するデータのうち、本機能で追加・変更されるものを定義する。

## 変更サマリ

| キー | 変更 |
|------|------|
| `tabOrder` | **新規追加**（`string[]`） |
| `groups` | スキーマ変更なし。**配列順が順序情報として使われなくなる**（集合として扱う）。名前の上限が30文字→20文字 |
| `items` | 変更なし（所属項目件数の集計に既存 `list()` を参照するのみ） |
| `settings` | 変更なし |

既存データのマイグレーションは不要。`tabOrder` が未保存の状態では正規化により
「未分類が先頭、以降は `groups` の配列順」となり、現在の表示順と一致する。

---

## エンティティ: TabOrder（新規）

タブの並び順を保持する。本機能における順序の**唯一の情報源**。

**ストレージキー**: `tabOrder`

**型**: `string[]`

**要素**: 以下のいずれか

| 値 | 意味 |
|----|------|
| `"__unassigned__"` | 未分類タブ（`groups` に実体を持たない仮想タブ。項目の `groupId === null` に対応） |
| グループの `id`（UUID） | 実グループのタブ |

**例**:

```json
["__unassigned__", "3f2b...", "9c1a...", "b74e..."]
```

### 制約

| 制約 | 内容 |
|------|------|
| 要素数 | 最大51（グループ上限50 + 未分類1） |
| `"__unassigned__"` の出現 | 正規化後は必ず1回だけ含まれる |
| 重複 | 正規化後は重複なし |
| 実在性 | 正規化後の要素は `"__unassigned__"` または `groups` に存在する `id` のみ |
| 網羅性 | 正規化後は `groups` の全 `id` を含む |

### 正規化（読み出しのたびに適用）

`normalizeTabOrder(storedOrder, groups)` が以下を順に適用する。
契約は [contracts/tab-order-contract.md](./contracts/tab-order-contract.md) を参照。

1. `groups` に存在しないIDを除去する
2. 重複IDは最初の出現のみ残す
3. `"__unassigned__"` が含まれていなければ先頭に追加する
4. `tabOrder` に含まれていない `groups` のIDを、`groups` の配列順で末尾に追加する

この正規化により FR-019（タブの重複表示・欠落が0件）が保存データの状態に関わらず成立する。

### ライフサイクル

| 契機 | 挙動 |
|------|------|
| 初回読み出し（キー未保存） | 既定値 `[]` から正規化され、`["__unassigned__", ...groups の配列順]` になる |
| グループ作成（`create`） | `tabOrder` は書き込まない。正規化のルール4により末尾に配置される（FR-019） |
| グループ削除（`remove`） | `tabOrder` から該当IDを除去して保存する（実在しないIDの蓄積を防ぐ） |
| グループ名変更（`rename`） | `tabOrder` は変化しない（IDが変わらないため） |
| 並び替え確定（`reorderTabs`） | 正規化済みの配列を丸ごと保存する |

書き込み契機の設計判断は [research.md](./research.md) の R-006 を参照。

### 派生する状態（永続化しない）

| 状態 | 導出 |
|------|------|
| 起動時に選択するタブ | `listTabOrder()` の先頭要素（FR-013） |
| タブバーの表示順 | `listTabOrder()` の順序（FR-012） |
| `▾` に併記する総数 | `listTabOrder().length`（FR-001。未分類を含む） |
| グループ削除後の選択タブ | 削除後の `listTabOrder()` の先頭要素（FR-030） |

## エンティティ: Group（既存・制約のみ変更）

**ストレージキー**: `groups`

**型**: `{ id: string, name: string }[]`

### 変更点

| 項目 | 変更前 | 変更後 |
|------|--------|--------|
| `name` の文字数上限 | 30 | **20**（FR-020） |
| 配列順の意味 | タブの表示順 | **意味を持たない**（集合として扱う。順序は `tabOrder` が保持） |
| `id` / `name` のスキーマ | — | 変更なし |
| グループ数の上限 | 50 | 変更なし |

### 検証ルール

| ルール | 適用箇所 | 挙動 |
|--------|---------|------|
| `name` は1〜20文字 | `create` / `rename` の**入力時のみ** | 違反時 `ValidationError("name", ...)` |
| グループ数は50件まで | `create` | 違反時 `ValidationError("limit", ...)` |
| 既に保存されている20文字超の `name` | — | **検証しない・切り詰めない**（FR-023）。表示は末尾省略で対応（FR-024） |

上限を下げても既存データを書き換えない理由は [research.md](./research.md) の R-012 を参照。

### 配列順に依存していた既存挙動の変更

| 箇所 | 変更前 | 変更後 |
|------|--------|--------|
| `sidepanel.js` の `renderTabs` | `groups` の配列順でタブを描画。未分類を先頭に固定 | `listTabOrder()` の順序で描画。未分類も並び替え対象（FR-010） |
| `sidepanel.js` の `init` | `groups[0].id`（無ければ未分類）を初期選択 | `listTabOrder()[0]` を初期選択（FR-013） |
| `sidepanel.js` の `deleteGroup` | 選択中グループの削除時に未分類へ切替 | 削除後の `listTabOrder()[0]` へ切替（FR-030） |
| 項目編集フォームのグループ選択（`populateGroupSelect`） | `groups` の配列順で `<option>` を描画 | 変更なし（`groups` の配列順のまま。並び順に合わせる要件はない） |

## エンティティ: Item（既存・変更なし）

**ストレージキー**: `items`

本機能では**参照のみ**。`groupId` ごとの件数集計（FR-003）と、グループ削除時に併せて削除される
件数の表示（FR-027）に使う。未分類の件数は `groupId === null` の項目数。

集計は `itemRepository.list()` を1回呼んで走査する。`itemRepository` への関数追加は行わない
（[research.md](./research.md) の R-009）。

---

## エンティティ: Settings（既存・変更なし）

**ストレージキー**: `settings`

本機能では読み書きしない。パネルの絞り込み文字列は永続化せず、パネルを閉じるときにクリアする
（[research.md](./research.md) の R-011）。パネルの開閉状態も永続化しない。

---

## UI上の一時状態（永続化しない）

`groupPanel.js` が保持する状態。ストレージには保存しない。

| 状態 | 内容 |
|------|------|
| パネルの開閉 | 開いているかどうか |
| 絞り込み文字列 | 入力中の文字列。パネルを閉じるときにクリアする |
| 行メニューの開閉 | どの行の三点リーダーメニューが開いているか |
| インライン編集の対象 | 名称変更中のグループID、または新規追加の入力行が表示されているか |
| ドラッグ中の状態 | `dragReorder.js` の内部状態（掴んだ行、開始座標、開始時のスクロール位置、現在の挿入位置） |

これらのうち「絞り込み文字列が空でない」「インライン編集中または入力行が表示中」の状態では
並び替えを開始できない（FR-016 / FR-025a）。
