# Feature Specification: 項目カードの並び替えハンドル（ドラッグ起点を掴み手に限定する）

**Feature Branch**: `feature/req-000013`

**Created**: 2026-09-04

**Status**: Draft

**Reqord Requirements**: [[req-000013]] 項目カードの並び替えハンドル（承認済み・要約は下記「Reqord要件要約」参照）

**Input**: User description: "req-000013「項目カードの並び替えハンドル」に基づく仕様作成。概要: 項目カードはどこを押しても並び替えのドラッグが始まり、コピーしようとしてポインタがわずかに動くと意図せず並び替えが始まる。グループの縦リストの行と同じ掴み手のアイコンをカード左端に追加し、並び替えのドラッグはその周辺を押した場合にのみ開始するようにする。"

## Reqord要件要約

- **req-000013（項目カードの並び替えハンドル）**: 項目カードは、カードのどこを押しても並び替えのドラッグが始まる。カード本体を押す操作は値のコピーにも割り当てられており、押した位置からの移動距離だけでコピーと並び替えを区別している。このためコピーしようとしてポインタがわずかに動くと、意図せず並び替えが始まる。コピーは繰り返し行う日常的な操作で、並び替えは並び順を決めるときだけの操作であり、頻度の高い操作をしようとして頻度の低い操作が誤って発動する形になっている。グループの縦リストの行と同じ掴み手のアイコンをカードの左端に追加し、並び替えのドラッグはそのアイコンとその周辺を押した場合にのみ開始するようにする。カード本体を押した場合はコピーだけが起きる。

本specは `008-item-reorder-unification` で統一した項目カードの並び替えのうち、**ポインタ操作の起点**を変更する。キーボードによる並び替え（同spec FR-004〜FR-010）は変更しない。

**既存specの扱い**: `003-sidepanel-list-enhancements` の FR-001（ドラッグ&ドロップによる並び替えを提供する）は維持する。提供すること自体は変わらず、**ドラッグを開始できる範囲がカード全体から掴み手とその周辺に狭まる**。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - コピーしようとして並び替わらない (Priority: P1)

利用者は値をコピーするためにカードを押すが、ポインタがわずかに動くと並び替えが始まってしまう。コピーは何度も行う操作なので、そのたびに順序が変わる危険がある。カード本体を押したときは並び替えが始まらないようにしたい。

**Why this priority**: 誤操作による順序の変化は、利用者が気づかないまま起きて元に戻す手段もない。本specの目的そのもの。

**Independent Test**: カード本体を押してポインタを大きく動かしてから離し、並び替えが起きていないことを確認する。また押して動かさずに離すと従来どおり値がコピーされることを確認する。

**Acceptance Scenarios**:

1. **Given** 項目一覧に複数のカードが表示されている、**When** カード本体を押してポインタを大きく動かす、**Then** 並び替えは開始されない（カードが浮かず、他のカードも退避しない）。
2. **Given** カード本体を押してポインタを大きく動かした、**When** 離す、**Then** 並び替えも値のコピーも起きない。
3. **Given** 項目一覧が表示されている、**When** カード本体を押して動かさずに離す、**Then** 従来どおり値がコピーされ、コピー完了の表示が出る。
4. **Given** カードのコピーボタン・三点リーダー・選択モード中のチェックボックスがある、**When** それらを押す、**Then** 従来どおりそれぞれの操作だけが起き、並び替えもカードのコピーも起きない。

---

### User Story 2 - 掴み手から並び替える (Priority: P1)

利用者は並び順を変えたい。どこを掴めば並び替えられるのかが見て分かり、そこから従来と同じようにドラッグしたい。グループの縦リストと同じ位置・同じ見た目であってほしい。

**Why this priority**: User Story 1 でカード本体からのドラッグを止めるため、代わりの起点を同時に用意しなければ並び替えができなくなる。2つは同時に満たす必要があり、いずれもP1とする。

**Independent Test**: 各カードの左端に掴み手のアイコンが表示されていることを確認し、そこを押してドラッグすると従来と同じ演出で並び替えが確定することを確認する。グループの縦リストの掴み手と見た目が同じであることを確認する。

**Acceptance Scenarios**:

1. **Given** 項目一覧が表示されている、**When** 各カードを確認する、**Then** カードの左端に掴み手のアイコンが表示されている。
2. **Given** 掴み手が表示されている、**When** グループの縦リストの行の掴み手と見比べる、**Then** 同じ字形・同じ配色である。
3. **Given** カードの掴み手を押した、**When** 目的の位置までドラッグして離す、**Then** 移動先のカードが退避して挿入位置が示され、離すと並び替えが確定する（従来のドラッグと同じ演出）。
4. **Given** カードの掴み手を押した、**When** 動かさずに離す、**Then** 並び替えも値のコピーも起きない。
5. **Given** 掴み手を押してドラッグ中、**When** 操作が中断される（他のウィンドウへの切り替えなど）、**Then** 従来どおり並び替えを確定せず元の順序に戻る。
6. **Given** 掴み手のアイコンが表示されている、**When** アイコンの字形の少し外側を押してドラッグする、**Then** 並び替えが開始される（当たり判定に余白が含まれている）。
7. **Given** 検索欄にキーワードが入力されている、**When** カードを確認する、**Then** 掴み手が表示されず、ポインタによる並び替えができない。
8. **Given** 選択モードが有効になっている、**When** カードを確認する、**Then** 掴み手が表示されず、ポインタによる並び替えができない。

---

### Edge Cases

- 掴み手を押してから閾値に達しないまま離した場合は何も起こらない。
- 掴み手を押してドラッグ中に操作が中断された場合は、並び替えを確定せず元の順序に戻す。
- 検索絞り込み中および選択モード中は掴み手を表示しない。この間はポインタによる並び替えができない（キーボードによる並び替えも従来どおり無効）。
- 項目が1件以下の場合、掴み手は表示されるがドラッグしても順序は変わらない。
- カード本体を押してポインタを動かした操作は、並び替えでもコピーでもない「何も起きない操作」として終わる。エラーも表示しない。
- 掴み手の追加によってカードの高さが変わってはならない。ドラッグの機構は行の高さを計測して挿入位置を求めるため、高さが変わると挿入位置の提示が狂う。

## Requirements *(mandatory)*

### Functional Requirements

#### 掴み手の表示

- **FR-001**: システムは、各項目カードの左端に掴み手のアイコンを表示しなければならない。
- **FR-002**: システムは、掴み手のアイコンをグループの縦リストの行で使っているものと同じ字形・同じ配色にしなければならない。
- **FR-003**: システムは、検索による絞り込みが有効な間、および選択モードが有効な間、掴み手を表示してはならない。
- **FR-004**: システムは、掴み手の追加によってカードの高さを変えてはならない。
- **FR-005**: システムは、掴み手をキーボードのフォーカスの対象にしてはならない。掴み手はポインタ操作のための要素である。

#### ドラッグの起点

- **FR-006**: システムは、項目カードの並び替えのドラッグを、掴み手とその周辺を押した場合にのみ開始しなければならない。
- **FR-007**: システムは、掴み手の当たり判定を、アイコンの字形より広い範囲にしなければならない。
- **FR-008**: システムは、カード本体（掴み手・コピーボタン・三点リーダー・チェックボックス以外の領域）を押した場合、並び替えを開始してはならない。
- **FR-009**: システムは、カード本体を押してポインタを動かしてから離した場合、並び替えも値のコピーも行ってはならない。
- **FR-010**: システムは、カード本体を押して動かさずに離した場合、従来どおり値をコピーしなければならない。
- **FR-011**: システムは、掴み手を押して動かさずに離した場合、並び替えも値のコピーも行ってはならない。
- **FR-012**: システムは、掴み手からのドラッグについて、ドラッグ中の演出（移動先の行の退避、挿入位置の提示、ドロップ時の吸着、自動スクロール、中断時の復帰）を従来どおり提供しなければならない。

#### 変更しないもの

- **FR-013**: システムは、キーボードによる並び替えとカードのフォーカス移動を変えてはならない。
- **FR-014**: システムは、グループの縦リストの並び替えの挙動を変えてはならない。

### Key Entities

本specで追加・変更する永続データはない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 項目一覧の100%のカードに掴み手のアイコンが表示される（検索絞り込み中と選択モード中を除く）。
- **SC-002**: カード本体を押してポインタを動かした場合、並び替えが開始される割合が0%である。
- **SC-003**: 掴み手を押してドラッグした場合、並び替えが開始される割合が100%である。
- **SC-004**: カード本体を押して動かさずに離した場合、従来どおり値がコピーされる。
- **SC-005**: 掴み手の当たり判定がアイコンの字形より広い範囲である。
- **SC-006**: 掴み手の追加前後でカードの高さが同一であり、ドラッグ中の挿入位置の提示に狂いが0件である。
- **SC-007**: キーボードによる並び替えとフォーカス移動に回帰が0件である。
- **SC-008**: グループの縦リストの並び替え（ドラッグ・キーボードとも）に回帰が0件である。

## Assumptions

- 掴み手の当たり判定の具体的な大きさは計画・実装フェーズで具体化する。アイコンの字形の周囲に余白を持たせ、ポインタで掴める範囲にする（FR-007 / SC-005）。
- 「ドラッグの開始を特定の要素に限定する」指定は、既存の並び替えの機構（`006-group-navigation` で切り出したポインタ操作の仕組み）への追加として実現する。カードとグループの縦リストで別の仕組みを持たない。
- グループの縦リストは、行のどこを押してもドラッグが開始される現在の挙動を維持する（FR-014）。グループの行を押す操作はグループの切替であり、コピーのように繰り返す操作ではないため、誤操作の代償が小さい。**カードと縦リストで起点の扱いが異なる点は意図的な差である。**
- 掴み手はカードの左端に置く。グループの縦リストの行と同じ位置にすることで、並び替えの起点が画面内で一貫する。
- 掴み手の表示・非表示の条件は、ポインタによる並び替えが有効な条件と一致させる（検索絞り込み中と選択モード中は非表示）。グループの縦リストで絞り込み中に掴み手を隠しているのと同じ方針。
- 項目の登録・編集・削除、マスク表示、項目名検索、選択モードによる一括削除・一括グループ変更、グループ側の機能はいずれも変更しない。
