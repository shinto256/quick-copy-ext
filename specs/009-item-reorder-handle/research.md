# Phase 0: Research — 項目カードの並び替えハンドル

**Feature**: `009-item-reorder-handle` | **Date**: 2026-09-04 | **Spec**: [spec.md](./spec.md)

spec の Assumptions で計画フェーズ送りとした項目を決定する。

---

## R-001: ドラッグ起点を限定する仕組み

**Decision**: `dragReorder` に `handleSelector` オプションを追加する。既存の `ignoreSelector` とは
別のオプションにする。

| オプション | 一致した要素を押したときの挙動 |
|-----------|------------------------------|
| `ignoreSelector` | ドラッグもタップ通知も**起こさない**（`pointerdown` を無視する） |
| `handleSelector` | **ここだけがドラッグを開始できる**。一致しない場所を押した場合はタップ通知のみ可能 |

**Rationale**:

- 求める挙動は3通りに分かれる。1つのオプションでは表せない。

  | 押した場所 | 閾値未満で離す | 閾値を超えて動かす |
  |-----------|--------------|------------------|
  | 掴み手 | 何も起きない | 並び替え |
  | カード本体 | コピー | 何も起きない |
  | コピーボタン・三点リーダー・チェックボックス | それぞれの操作 | それぞれの操作 |

  3列目は `ignoreSelector` が既に担っている。1列目と2列目の違いが `handleSelector` の役目。
- グループの縦リストは `handleSelector` を渡さない。指定がなければ「行全体がドラッグ可能」という
  現在の挙動が変わらない（spec FR-014）。後方互換の追加になる。
- カードとグループで別の仕組みを持たない、という spec Assumptions の方針を満たす。

**Alternatives considered**:

- **`ignoreSelector` にカード本体のセレクタを足す**: カード本体を無視するとタップでのコピーも
  起きなくなる（spec FR-010 に反する）。
- **カードの `keydown`/`pointerdown` を呼び出し側で自前に処理する**: `dragReorder` が
  `setPointerCapture` を握るため、呼び出し側で二重に `pointerdown` を監視すると判定が競合する。
- **掴み手だけを `rowSelector` にする**: `rowSelector` は「並び替える単位」を指すもので、
  ドラッグ後にDOMを並べ替える対象でもある。掴み手を単位にすると並べ替えの対象がずれる。

## R-002: 掴み手を押して動かさずに離した場合の扱い

**Decision**: 何も起こさない（`onActivate` を呼ばない）。

**Rationale**:

- 掴み手は並び替え専用の起点（spec FR-011）。ここを押して離した操作にコピーを割り当てると、
  「掴み手を押したのにコピーされた」という予測しにくい結果になる。
- 実装上は `handleSelector` に一致する場所からの操作について `onActivate` を呼ばないようにする。
  掴み手を「ドラッグ専用」として扱うのが最も説明しやすい。

**Alternatives considered**:

- **掴み手でもタップでコピーする**: カード本体と挙動が同じになり、掴み手を分けた意味が薄れる。

## R-003: 掴み手の当たり判定の大きさ

**Decision**: アイコンの字形の周囲に上下 `--space-2`（8px）・左右 `--space-2`（8px）の余白を
`padding` で持たせる。カードの高さは変えない。

**Rationale**:

- `padding` で当たり判定を広げれば、アイコンの字形より広い範囲でドラッグを開始できる
  （spec FR-007 / SC-005）。
- カードの高さを変えないことが前提（spec FR-004 / SC-006）。カードは
  `display: flex; align-items: center` で、既存のコピーボタンや三点リーダーより背の低い要素を
  足しても高さは変わらない。掴み手の高さ（アイコン + 上下8px）は既存のコピーボタン（18pxのアイコン +
  余白）以下に収まるため、カードの高さを押し上げない。
- グループの縦リストの掴み手（`.group-row-handle`）は行の高さが固定されているため `padding` を
  持っていない。カード側は高さが可変なので、`padding` で当たり判定を作る必要がある。
  **見た目（字形・配色）は揃え、当たり判定の作り方だけ変える。**

**Alternatives considered**:

- **固定の幅・高さを指定する**: カードの高さが可変なので、固定値だと行によって余白の見え方が
  変わる。`padding` の方が素直。
- **アイコンの字形のみ**: 掴みにくく、spec FR-007 を満たさない。

## R-004: 掴み手の表示条件とフォーカス

**Decision**:

- 検索絞り込み中（`searchTerm` が空でない）または選択モード中（`selectionMode`）は、
  **掴み手の要素そのものを描画しない**（spec FR-003）。
- 掴み手は `<span>` で作り、`tabindex` を付けない。`aria-hidden="true"` を付ける（spec FR-005）。

**Rationale**:

- 表示条件をポインタによる並び替えが有効な条件（既存の `canDrag: () => !searchTerm && !selectionMode`）と
  一致させる。操作できないものを表示しない。
- グループの縦リストは絞り込み中に掴み手を CSS の `visibility: hidden` で隠しているが、
  カード側は**要素を描画しない**方式にする。カードは `createItemCard` が条件分岐で要素を組み立てる
  構造（撤去した上下移動ボタンも `if (!searchTerm && !selectionMode)` の中にあった）なので、
  同じ形にするのが素直。表示のブレはない（どちらも見えない）。
- `aria-hidden="true"` は装飾的な字形を読み上げの対象から外すため。既存の `.group-row-handle` と
  同じ扱い。

**Alternatives considered**:

- **CSS で隠す**: カード側は要素の有無で条件分岐する構造なので、CSSに条件を持たせると
  条件が2箇所に散る。
