# Feature Specification: 拡張機能名・説明の多言語対応

**Feature Branch**: `feature/req-000017`

**Created**: 2026-09-10

**Status**: Draft

**Input**: User description: "req-000017: 拡張機能名・説明の多言語対応。現状 manifest の名称（Quick Copy）と説明（登録した定型文字列をワンクリックでコピーできる拡張機能）が単一言語のハードコードで既定言語も未設定のため、英語環境のブラウザでも拡張機能管理画面やストア掲載情報に日本語の説明が表示される。ブラウザの表示言語に応じて拡張機能の名称と説明が切り替わるようにする。既存のサイドパネル内の言語切替（req-000015）は利用者が明示的に選ぶ別系統として維持し、変更しない。対象外: サイドパネル内の表示文字列、Chrome Web Store Developer Dashboard 上の掲載情報の入力、日本語・英語以外の言語追加。"

## Clarifications

### Session 2026-09-10

- Q: 英語環境で表示する拡張機能の説明文を、どの文言にしますか？ → A: 日本語版の意味を保った直訳とする（`Copy your registered text snippets to the clipboard with a single click.`）。マスク表示やグループの訴求は本要件では説明文に含めず、ストア掲載情報の詳細説明（対象外）で扱う

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 英語環境で拡張機能の内容を理解できる (Priority: P1)

ブラウザを英語表示で使っている利用者が、拡張機能管理画面やストアの掲載情報を見たときに、拡張機能の名称と説明を英語で読める。何をする拡張機能なのかを理解したうえでインストールし、利用を続けられる。

**Why this priority**: 本要件の中核価値。現状は英語環境でも日本語の説明が表示され、英語話者には何の拡張機能か判別できない。ストア公開時に最初に読まれる情報であり、インストールの判断に直結する。

**Independent Test**: ブラウザの表示言語を英語に設定して拡張機能管理画面を開き、名称と説明が英語で表示されることを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** ブラウザの表示言語が英語に設定されている, **When** 利用者が拡張機能管理画面を開く, **Then** 拡張機能の名称と説明が英語で表示される
2. **Given** ブラウザの表示言語が英語に設定されている, **When** 利用者がストアの掲載情報を開く, **Then** 拡張機能の名称と説明が英語で表示される
3. **Given** ブラウザの表示言語が `en-US` や `en-GB` のように地域を含む英語に設定されている, **When** 利用者が拡張機能管理画面を開く, **Then** 拡張機能の名称と説明が英語で表示される

---

### User Story 2 - 日本語環境の表示が変わらない (Priority: P2)

すでに本拡張機能を日本語環境で使っている利用者が、この変更の後も従来と同じ日本語の名称と説明を見られる。

**Why this priority**: 既存利用者に対する回帰防止。新しい価値を加えるものではないが、既存の体験を壊さないことは公開前の品質として必須。P1の実現手段が既存の日本語表示を壊す形になっていないかを検証する役割も持つ。

**Independent Test**: ブラウザの表示言語を日本語に設定して拡張機能管理画面を開き、変更前と同じ名称と説明が表示されることを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** ブラウザの表示言語が日本語に設定されている, **When** 利用者が拡張機能管理画面を開く, **Then** 拡張機能の名称と説明が日本語で表示される
2. **Given** ブラウザの表示言語が日本語に設定されている, **When** 利用者が拡張機能を読み込む, **Then** 警告やエラーが表示されずに読み込みが完了する

---

### User Story 3 - 未対応の言語環境でも意味のある表示になる (Priority: P3)

日本語でも英語でもない表示言語のブラウザを使っている利用者が、拡張機能管理画面を開いたときに、空欄や壊れた表示ではなく既定の言語の名称と説明を読める。

**Why this priority**: 対応言語を2つに限る判断の裏側で必ず発生するケース。頻度は低いが、名称が解決できないと拡張機能自体が読み込めなくなるため、破綻しないことを保証する必要がある。

**Independent Test**: ブラウザの表示言語をドイツ語などに設定して拡張機能管理画面を開き、既定の言語の名称と説明が表示されることを確認するだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** ブラウザの表示言語が日本語・英語以外（例: ドイツ語）に設定されている, **When** 利用者が拡張機能管理画面を開く, **Then** 既定の言語である日本語の名称と説明が表示される
2. **Given** ブラウザの表示言語が日本語・英語以外に設定されている, **When** 利用者が拡張機能を読み込む, **Then** 名称や説明が空欄にならず、警告やエラーも表示されない

---

### Edge Cases

- ブラウザの表示言語が地域を含むコード（`en-US`、`en-GB`、`ja-JP`）のとき、地域を除いた言語として解決され、対応する言語の名称と説明が表示される。
- 利用者がサイドパネル内で選んでいる表示言語と、ブラウザの表示言語が食い違っているとき（例: ブラウザは日本語、サイドパネル内の設定は英語）、拡張機能の名称と説明はブラウザの表示言語に従い、サイドパネル内の文字列は利用者の選択に従う。両者は互いに影響しない。
- 対訳の一部が欠けているとき、拡張機能の名称が解決できずに読み込みが失敗する可能性がある。名称と説明の両方について、対応するすべての言語で対訳が揃っている必要がある。
- 既定の言語として指定した言語の対訳が存在しないとき、拡張機能の読み込みが失敗する。既定の言語には必ず対訳が存在する言語を指定する必要がある。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 拡張機能の名称と説明は、ブラウザの表示言語が英語のとき英語で表示されなければならない。
- **FR-002**: 拡張機能の名称と説明は、ブラウザの表示言語が日本語のとき日本語で表示されなければならない。
- **FR-003**: 拡張機能の名称と説明は、ブラウザの表示言語が日本語・英語のいずれでもないとき、既定の言語である日本語で表示されなければならない。
- **FR-004**: 拡張機能の名称と説明の表示言語は、ブラウザの表示言語のみによって決まらなければならない。利用者がサイドパネル内で選択した表示言語によって変化してはならない。
- **FR-005**: 利用者がサイドパネル内で表示言語を選択・切り替える既存の振る舞いは、変更されてはならない。
- **FR-006**: 拡張機能は、対応するすべての表示言語環境において、警告およびエラーなしで読み込まれなければならない。
- **FR-007**: 拡張機能の名称は、いずれの表示言語においても製品名として同一の呼称を保たなければならない。
- **FR-008**: 英語環境で表示する説明は、日本語の説明と同じ意味内容を伝えなければならない。日本語版にない機能の訴求を英語版だけに含めてはならない。
- **FR-009**: 拡張機能の説明は、いずれの表示言語においてもストアが定める説明の長さの上限（132文字）を超えてはならない。

### Key Entities

- **拡張機能メタデータ**: ブラウザおよびストアが利用者に提示する拡張機能の名称と説明。表示言語ごとの対訳を持つ。
- **表示言語**: ブラウザの設定によって決まる言語。利用者が拡張機能の外側で設定するものであり、拡張機能から変更できない。サイドパネル内の表示言語とは別の概念。
- **既定の言語**: 利用者の表示言語に対応する対訳が存在しないときに使う言語。本要件では日本語とする。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ブラウザの表示言語を英語に設定した環境で拡張機能管理画面を開いたとき、表示される名称と説明に日本語の文字が0文字である。
- **SC-002**: ブラウザの表示言語を日本語に設定した環境で拡張機能管理画面を開いたとき、変更前と同じ名称と説明が表示される。
- **SC-003**: 日本語・英語以外の表示言語を3種類以上（例: ドイツ語・フランス語・中国語）で確認したとき、いずれの環境でも日本語の名称と説明が表示され、空欄になるものが0件である。
- **SC-004**: 対応するすべての表示言語環境で拡張機能を読み込んだとき、表示される警告およびエラーが0件である。
- **SC-005**: 既存の自動テストが全件パスする（2026-09-10時点で10ファイル・209件）。
- **SC-006**: ブラウザの表示言語とサイドパネル内で選択した表示言語が異なる組み合わせ（日本語×英語、英語×日本語）の2通りで、拡張機能の名称・説明とサイドパネル内の文字列がそれぞれ意図した言語で表示される。
- **SC-007**: 拡張機能の名称が、日本語環境と英語環境で同一の文字列として表示される。
- **SC-008**: 日本語・英語それぞれの説明の文字数が132文字以内である。
- **SC-009**: 英語環境で表示される説明が、Assumptions に定めた文言と完全に一致する。

## Assumptions

- 対応する言語は日本語と英語の2つに限る。既定の言語は日本語とする。サイドパネル内の表示言語の既定が日本語であることと揃える判断。
- 拡張機能の名称は英語環境でも `Quick Copy` のままとする。製品名であり翻訳の対象としない。表示言語によって変わるのは説明のみ、および将来追加される可能性のある名称以外のメタデータ。
- 説明の英語表記は本要件で新たに用意し、`Copy your registered text snippets to the clipboard with a single click.`（72文字）とする。既存の日本語の説明文（登録した定型文字列をワンクリックでコピーできる拡張機能）の意味を保った直訳であり、日本語版と英語版で伝える内容を対等に保つ判断。マスク表示やグループの訴求は説明文には含めず、ストア掲載情報の詳細説明（対象外）で扱う。
- ブラウザの表示言語は利用者のOSまたはブラウザの設定によって決まり、拡張機能から取得はできても変更はできない。実行中に切り替わることも想定しない。
- サイドパネル内の表示言語を扱う既存の仕組み（req-000015 で実装）は本要件では変更しない。名称・説明の言語とサイドパネル内の言語は決定方法が異なるため、別系統として併存させる。
- Chrome Web Store Developer Dashboard 上の掲載情報（説明文・スクリーンショット等）の入力は本要件の範囲外とする。本要件は掲載情報を言語別に入力できる前提を整えるところまでを担う。
- 検証はブラウザの表示言語設定を切り替えて手動で行う。ブラウザの表示言語に依存する表示の自動テストは本要件では追加しない。
