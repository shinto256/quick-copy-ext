# Feature Specification: 項目並び替え操作の統一（カードのキーボード操作と上下移動ボタンの撤去）

**Feature Branch**: `feature/req-000012`

**Created**: 2026-09-04

**Status**: Draft

**Reqord Requirements**: [[req-000012]] 項目並び替え操作の統一（承認済み・要約は下記「Reqord要件要約」参照）

**Input**: User description: "req-000012「項目並び替え操作の統一」に基づく仕様作成。概要: 項目カードとグループの縦リストで並び替えの操作体系が揃っていない。カードはドラッグ操作と各カード左端の上下移動ボタン、グループの縦リストはドラッグ操作とキーボード操作。カードの上下移動ボタンを撤去し、グループと同じ2手段に統一する。キーボードからの到達性はカード自体をフォーカス可能にして維持する。"

## Reqord要件要約

- **req-000012（項目並び替え操作の統一）**: 項目一覧のカードとグループの縦リストは、どちらも並び替えができるが操作手段が揃っていない。カードにはドラッグ操作と各カード左端の上下移動ボタン（`▲▼`）があり、グループの縦リストにはドラッグ操作とキーボード操作（修飾キー＋矢印）がある。同じ「並び替え」に2通りの操作体系が並存しており、利用者は画面ごとに操作を覚え直す必要がある。またカードの上下移動ボタンは各カードの横幅を占有しており、名前と値の表示領域を狭めている。カードの上下移動ボタンを撤去し、グループの縦リストと同じ「ドラッグ操作とキーボード操作」の2手段に統一する。キーボードからの到達性は、カード自体をフォーカス可能にして修飾キー＋矢印で並び替えられるようにすることで維持する。

本specは `003-sidepanel-list-enhancements` で実装済みの項目並び替えと、`007-sidepanel-keyboard` で実装済みのグループの縦リストのキーボード操作を対象にする。

**既存specの置き換え**: 本specの完了により、`003-sidepanel-list-enhancements` の以下が置き換わる。

| 置き換わる対象 | 内容 | 本specでの扱い |
| --- | --- | --- |
| spec 003 FR-002 | 各カードのケバブメニューに「上へ移動」「下へ移動」を追加し、ドラッグ操作の代替手段として提供する | 撤去する。代替手段はキーボード操作が担う（本spec FR-004〜FR-009） |
| spec 003 SC-001 | 並び替えを1操作（ドラッグ1回、または上下移動ボタン1回のクリック）で完了できる | 「ドラッグ1回、またはキーボードの移動操作1回」に読み替える（本spec SC-002） |

spec 003 FR-001（ドラッグ&ドロップによる並び替え）、FR-003（永続化）、FR-004（絞り込み中の無効化）は変更しない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - キーボードで項目を並び替え、コピーする (Priority: P1)

キーボードだけを使う利用者は、項目の並び替えに各カードの上下移動ボタンを使っている。グループの縦リストでは修飾キー＋矢印で並び替えられるのに、カードでは操作が違う。同じ操作で並び替えたい。

**Why this priority**: 上下移動ボタンを撤去する前に、キーボードからの到達性を代替手段で確保しておく必要がある。順序を逆にすると、一時的にキーボードで並び替えられない状態が生まれる。

**Independent Test**: マウスを使わずに項目カードにフォーカスを移し、グループの縦リストと同じキー操作で任意の項目を一覧の先頭まで移動でき、決定キーで値をコピーできることを確認する。

**Acceptance Scenarios**:

1. **Given** 項目一覧に複数のカードが表示されている、**When** キーボードでフォーカスを進める、**Then** カードにフォーカスが移り、フォーカス位置が視覚的に判別できる。表示はグループの縦リストの行と同じ表現である。
2. **Given** カードにフォーカスがある、**When** 1つ上へ移動するキー操作を行う、**Then** そのカードが1つ上の位置へ移動し、順序が保存される。**キーはグループの縦リストと同一である。**
3. **Given** カードを移動させた直後、**When** フォーカス位置を確認する、**Then** フォーカスは移動したカードに残っており、続けて同じキー操作で更に移動できる。
4. **Given** 一覧の最下部のカードにフォーカスがある、**When** 上へ移動するキー操作を繰り返す、**Then** 先頭まで移動でき、その間ポインタ操作を一度も使わない。
5. **Given** カードにフォーカスがある、**When** 決定キーを押す、**Then** そのカードの値がクリップボードへコピーされ、コピー完了の表示が出る（ポインタでカードを押したときと同じ結果）。
6. **Given** 先頭のカードにフォーカスがある、**When** 上へ移動するキー操作を行う、**Then** 順序は変わらず、エラーも表示されない。
7. **Given** 末尾のカードにフォーカスがある、**When** 下へ移動するキー操作を行う、**Then** 順序は変わらず、エラーも表示されない。
8. **Given** 検索欄にキーワードが入力されている、**When** カードにフォーカスして移動のキー操作を行う、**Then** 並び替えは行われない。
9. **Given** 選択モードが有効になっている、**When** カードにフォーカスして移動のキー操作または決定キーを押す、**Then** 並び替えもコピーも行われない。
10. **Given** カード内のコピーボタン・三点リーダー・チェックボックスにフォーカスがある、**When** 移動のキー操作を行う、**Then** 並び替えは行われない（それぞれの要素の通常の操作を妨げない）。
11. **Given** 並び替えを行った、**When** サイドパネルを閉じて再度開く、**Then** 並び替えた順序が保持されている。

---

### User Story 2 - カードの表示領域を名前と値に充てる (Priority: P2)

利用者は、狭いサイドパネルで項目の名前と値をできるだけ広く読みたい。各カード左端の上下移動ボタンが横幅を占有しており、長い名前や値が早く省略される。

**Why this priority**: User Story 1 でキーボードからの到達性を確保した後でなければ撤去できない。撤去自体は表示領域の改善であり、機能の追加ではないためP2とする。

**Independent Test**: 項目一覧のカードに上下移動ボタンが表示されていないこと、その分だけ名前と値の表示幅が広がっていること、並び替えがドラッグ操作とキーボード操作の両方で行えることを確認する。

**Acceptance Scenarios**:

1. **Given** 項目一覧が表示されている、**When** 各カードを確認する、**Then** 上下移動ボタンが表示されていない。
2. **Given** 項目一覧が表示されている、**When** 各カードに残っている操作要素を確認する、**Then** コピーボタンと三点リーダーのみである（選択モード中はチェックボックスが加わる）。
3. **Given** 上下移動ボタンの撤去前と同じ名前・値を持つ項目がある、**When** カードの表示を比較する、**Then** 名前と値の表示幅が広がっている。
4. **Given** 上下移動ボタンが撤去されている、**When** カードをドラッグして別の位置で離す、**Then** 従来どおり並び替えが確定する。
5. **Given** 上下移動ボタンが撤去されている、**When** カードをキーボードで並び替える、**Then** User Story 1 のとおり並び替えられる（並び替えの手段が失われていない）。

---

### Edge Cases

- 先頭のカードで上へ移動、末尾のカードで下へ移動するキー操作を行った場合は、順序を変更せず何も起こらない。エラーも表示しない。
- 一覧に表示されている項目が1件以下の場合、移動のキー操作は順序を変えない。
- 検索で絞り込んでいる間はキーボードによる並び替えを行わない。絞り込みを解除すれば行える。既存のドラッグ操作と同じ条件。
- 選択モード中はキーボードによる並び替えも決定キーによるコピーも行わない。既存の「選択モード中は個別のカード操作を無効化する」方針と整合させる。
- 並び替えの永続化に失敗した場合は、既存の挙動を維持する（一覧を再描画して保存済みの順序に戻す）。
- 移動のキー操作を押し続けた場合も、1回の入力で1つ分の移動として扱う。

## Requirements *(mandatory)*

### Functional Requirements

#### カードのフォーカスと決定キー

- **FR-001**: システムは、項目カードをキーボードでフォーカスできるようにしなければならない。
- **FR-002**: システムは、カードのフォーカス表示に既存のフォーカス表現を用いなければならない。カード専用の独自の表現を追加してはならない。
- **FR-003**: システムは、カードにフォーカスがある状態で決定キーが押された場合、そのカードの値をクリップボードへコピーしなければならない。ポインタでカードを押したときと同じ結果にしなければならない。

#### キーボードによる並び替え

- **FR-004**: システムは、カードにフォーカスがある状態で、そのカードを1つ上へ移動させるキー操作と1つ下へ移動させるキー操作を提供しなければならない。
- **FR-005**: システムは、並び替えに割り当てるキーを、グループの縦リストの並び替え（`007-sidepanel-keyboard`）と**同一**にしなければならない。
- **FR-006**: システムは、移動のたびに順序を永続化しなければならない。
- **FR-007**: システムは、移動後もフォーカスを移動したカードに保たなければならない。連続した入力で更に移動できなければならない。
- **FR-008**: システムは、先頭のカードに対する上への移動、および末尾のカードに対する下への移動では、順序を変更してはならない。エラーを表示してもならない。
- **FR-009**: システムは、検索による絞り込みが有効な間、および選択モードが有効な間、キーボードによる並び替えと決定キーによるコピーを行ってはならない。
- **FR-010**: システムは、カード内の操作要素（コピーボタン・三点リーダー・チェックボックス）にフォーカスがある間、移動のキー操作および決定キーを並び替え・コピーとして解釈してはならない。

#### 上下移動ボタンの撤去

- **FR-011**: システムは、各カードから上下移動ボタンを撤去しなければならない。
- **FR-012**: システムは、カードに残す操作要素をコピーボタンと三点リーダーのみとしなければならない（選択モード中はチェックボックスを加える）。
- **FR-013**: システムは、上下移動ボタンの撤去によって空いた領域を名前と値の表示に充てなければならない。
- **FR-014**: システムは、上下移動ボタンの撤去によってポインタ操作（ドラッグでの並び替え、タップでのコピー、それらの判定）を変えてはならない。

### Key Entities

本specで追加・変更する永続データはない。項目の並び順を既存の手段で更新するのみ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 項目一覧に上下移動ボタンが0件である。
- **SC-002**: 利用者は、項目の並び替えを1操作（ドラッグ1回、またはキーボードの移動操作1回）で完了できる。
- **SC-003**: 利用者は、ポインタ操作を一度も使わずに、任意の項目を一覧の先頭へ移動できる。
- **SC-004**: 利用者は、ポインタ操作を一度も使わずに、任意の項目の値をコピーできる。
- **SC-005**: 項目カードとグループの縦リストで、並び替えに割り当てられたキーが同一である。
- **SC-006**: 検索絞り込み中および選択モード中は、キーボードによる並び替えが100%行われない。
- **SC-007**: カードのフォーカス表示は、グループの縦リストの行および既存のボタン・入力欄のフォーカス表示と同一の見た目である。
- **SC-008**: 本specの変更によって、既存のポインタ操作（ドラッグでの並び替え、タップでのコピー、5px閾値の判定）に回帰が0件である。

## Assumptions

- 決定キーおよび移動のキー操作は、グループの縦リストで採用済みのものと同じキーを使う（FR-005）。具体的なキーは `007-sidepanel-keyboard` の決定に従い、本specで独自に定めない。
- カードをフォーカス可能にする手段は、グループの縦リストの行と同じ方式を採る。フォーカス表示は既存のグローバルなフォーカス表現に任せ、要素をフォーカス可能にするだけで見た目が揃う構成とする（SC-007）。
- 並び順の組み替えとキーボード操作の判定は、グループの縦リストで実装済みの仕組みを流用する。同じ振る舞いを2箇所に書き分けない。
- 並び替えの永続化は既存の項目並び替えAPIをそのまま使う。永続データの構造・保存先は変更しない。
- カードは値の長さによって高さが変わる。既存のドラッグ機構は可変高に対応済みであり、本specでその前提は変わらない。
- 既存のポインタ操作の判定（押した位置からの移動距離でタップと並び替えを区別する）の副作用として、カードをポインタで押したときにカード自体へフォーカスが移らない可能性がある。ポインタで押した場合は値がコピーされるため実害はなく、フォーカスの起点はキーボードによる移動とする。グループの縦リストと同じ扱い。
- 項目一覧へのキーボードによるフォーカス移動は、カードごとに1つのタブストップを設ける方式とする。コピーボタン・三点リーダーは従来どおり個別にフォーカスできる。
- ショートカットキーによるコマンド実行、スクリーンリーダー向けのライブリージョン通知はスコープ外とする。
- 項目の登録・編集・削除、マスク表示、項目名検索、選択モードによる一括削除・一括グループ変更、グループ側の機能はいずれも変更しない。
