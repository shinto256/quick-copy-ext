# Feature Specification: サイドパネル一覧機能拡張(並び替え・テーマ手動切替・一括削除)

**Feature Branch**: `003-sidepanel-list-enhancements`

**Created**: 2026-08-28

**Status**: Draft

**Reqord Requirements**: [[req-000005]] 項目並び替え機能 / [[req-000006]] テーマ手動切替機能 / [[req-000007]] 項目一括削除機能（すべて承認済み・要約は下記「Reqord要件要約」参照）

**Input**: User description: "サイドパネルUI(002-side-panel-ui)への追加機能3件をまとめて実装する。1. 項目並び替え機能: 一覧内の項目(選択中タブ内)の表示順をドラッグ&ドロップ等で変更可能にし、永続化する。グループをまたぐ並び替えは対象外。検索絞り込み中は対象外。2. テーマ手動切替機能: 既存のシステム設定自動追従に加え、自動/ライト固定/ダーク固定の3択をユーザーが手動選択できるようにする。デフォルトは自動。パネル内で完結。3. 項目一括削除機能: 各カードにチェックボックスを設け、複数項目を選択して一括削除できるようにする。確認ダイアログを経て確定、取り消し不可。タブ切替・検索実行時は選択状態をリセットする。既存のstorage層を拡張し、既存spec 002-side-panel-uiの実装に対する追加機能として新規specに切り出す。"

## Reqord要件要約

- **req-000005（項目並び替え機能）**: 一覧内(選択中タブ内)の項目の表示順をユーザーが任意に変更できる機能。並び順は永続化し、再度開いても維持する。グループをまたぐ並び替えは対象外。
- **req-000006（テーマ手動切替機能）**: 表示テーマを「自動(システム設定追従)/ライト固定/ダーク固定」の3択で手動設定できる機能。デフォルトは自動。設定はパネル内で完結し永続化する。
- **req-000007（項目一括削除機能）**: 一覧から複数項目を選択し、まとめて削除できる機能。確認ダイアログを経て確定し、取り消し不可。

本specはこれら3要件を、既存spec `002-side-panel-ui`（サイドパネルUI）に対する追加機能として実装する。002-side-panel-uiの既存機能(タブ+カード一覧、インライン登録編集、マスク切替、検索、システム設定への自動テーマ追従)は変更しない。

## Clarifications

### Session 2026-08-28

- Q: 新規登録した項目は、選択中タブの一覧内で先頭と末尾のどちらに追加されるか？ → A: 末尾に追加する（既存のstorage実装の登録順に近い挙動を踏襲する）。
- Q: 選択モードで何も削除せずに通常表示へ戻る明示的な操作は必要か？ → A: 必要。「キャンセル/選択解除」操作を選択モードのUIに用意する。
- Q: 手動並び替え(req-000005)に加えて、「登録順」等のソート基準切替機能も本specのスコープに含めるか？ → A: 含めない。本specは手動並び替えのみとし、ソート基準切替は将来の別要件として切り出す。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 項目の並び順を自分で決める (Priority: P1)

利用者は、よく使う項目を一覧の上位に置くなど、選択中のグループ内で項目の並び順を自分の使いやすいように変更したい。

**Why this priority**: 登録項目が増えるほど、利用頻度の高い項目を素早く見つけたいというニーズが強くなる。既存の一覧・コピー体験(002-side-panel-ui)を底上げする基本機能。

**Independent Test**: 同一タブ内に複数項目がある状態で、ドラッグ&ドロップまたはケバブメニューの「上へ/下へ移動」で並び順を変更し、パネルを閉じて再度開いても変更後の順序が維持されることを確認する。

**Acceptance Scenarios**:

1. **Given** 選択中タブ内に複数項目が一覧表示されている、**When** カードをドラッグして別の位置にドロップする、**Then** 一覧の表示順が即座にドロップ位置に応じて変わる。
2. **Given** カードのケバブメニューを開いている、**When** 「上へ移動」または「下へ移動」を選択する、**Then** 対象カードが一覧内で1つ上または下の位置に移動する。
3. **Given** 並び順を変更した直後、**When** パネルを閉じて再度開く、**Then** 変更後の並び順が維持されて表示される。
4. **Given** 検索キーワードで絞り込み中、**When** カードの並び替えを試みる、**Then** 並び替え操作は行えない(絞り込み解除後にのみ並び替え可能)。

---

### User Story 2 - テーマをライト/ダークに固定する (Priority: P3)

利用者は、OS側の設定に関わらず、常にライトまたはダークの決まったテーマでパネルを使いたい。

**Why this priority**: システム設定への自動追従(002-side-panel-uiで実装済み)で大多数の利用者は満足するが、一部の利用者は固定表示を望む。影響範囲が限定的な補助機能のため優先度は低い。

**Independent Test**: テーマ設定で「ライト固定」を選択し、OS側のテーマ設定をダークに変更してもパネルがライト表示のままであることを確認する。

**Acceptance Scenarios**:

1. **Given** ヘッダーのメニューからテーマ設定を開く、**When** 「ライト固定」「ダーク固定」「自動」のいずれかを選択する、**Then** 選択直後にパネルの表示テーマが即座に切り替わる。
2. **Given** 「ダーク固定」を選択した状態、**When** OS側のテーマ設定をライトに変更する、**Then** パネルの表示はダークのまま変化しない。
3. **Given** テーマ設定を変更した直後、**When** パネルを閉じて再度開く、**Then** 直前に選択したテーマ設定が維持されている。
4. **Given** 初回利用時(未設定状態)、**When** パネルを開く、**Then** 「自動」設定(既存のシステム設定追従動作)が適用されている。

---

### User Story 3 - 不要な項目をまとめて削除する (Priority: P2)

利用者は、不要になった項目が複数ある場合に、1件ずつ削除するのではなく、まとめて選択して一度に削除したい。

**Why this priority**: 登録数が増えるほど整理の手間が増す。個別削除(002-side-panel-uiで実装済み)を補完する効率化機能。

**Independent Test**: 一覧内で複数項目を選択し、一括削除操作を行うと、確認後に選択したすべての項目が一覧から削除され、選択しなかった項目は残ることを確認する。

**Acceptance Scenarios**:

1. **Given** 一覧の選択モードを開始する操作を行う、**When** 選択モードに入る、**Then** 各カードにチェックボックスが表示される。
2. **Given** 選択モード中、**When** 複数のカードのチェックボックスを選択する、**Then** 選択件数が分かる形で表示され、一括削除操作が可能になる。
3. **Given** 複数項目を選択した状態、**When** 一括削除操作を行う、**Then** 確認ダイアログが表示され、承認すると選択したすべての項目が一覧・保存データから削除される。
4. **Given** 一括削除完了直後、**When** 一覧を確認する、**Then** 選択していなかった項目は変更なく残っている。
5. **Given** 選択モード中に項目を選択している、**When** タブを切り替える、または検索キーワードを入力する、**Then** 選択状態はリセットされる(選択モード自体も終了する)。
6. **Given** 選択モード中(削除は行わない)、**When** 「キャンセル/選択解除」操作を行う、**Then** 選択状態が破棄され、チェックボックスのない通常の一覧表示に戻る。

### Edge Cases

- 並び替え対象のタブに項目が1件以下の場合、並び替え操作(ドラッグ・上下移動)は実質的に効果を持たない(エラーにはしない)。
- グループ削除により項目が「未分類」タブへ移動した場合、移動後の並び順は移動元の並び順に関わらず「未分類」タブの末尾に追加する。
- 選択モード中に対象タブの項目が0件になった場合(他の操作で削除された等)、選択モードは自動的に終了する。
- 一括削除で選択件数が0件のまま削除操作を行った場合、何も削除されず、エラー表示もしない(操作自体を無効化する)。
- テーマ設定の保存に失敗した場合、表示上は選択したテーマを維持しつつ、次回起動時に「自動」に戻る可能性があることを通知する(既存のマスク設定保存失敗時の挙動[[req-000003]]に準拠)。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、選択中タブ内の項目について、ドラッグ&ドロップによる並び替えを提供しなければならない。
- **FR-002**: システムは、各カードのケバブメニューに「上へ移動」「下へ移動」を追加し、ドラッグ操作の代替手段として並び替えできるようにしなければならない。
- **FR-003**: システムは、並び替え後の順序を永続化し、パネルを再度開いた際も同じ順序で一覧表示しなければならない。
- **FR-004**: システムは、検索キーワードによる絞り込み表示中は、並び替え操作(ドラッグ・上下移動とも)を無効化しなければならない。
- **FR-005**: システムは、グループ削除等により項目の所属タブが変わった場合、移動後のタブ内で当該項目を末尾に配置しなければならない。
- **FR-005a**: システムは、新規登録された項目を、所属タブの一覧内で末尾に追加しなければならない。
- **FR-006**: システムは、テーマ設定として「自動」「ライト固定」「ダーク固定」の3つの選択肢を提供しなければならない。デフォルトは「自動」とする。
- **FR-007**: システムは、テーマ設定の変更をパネル内の操作(画面遷移を伴わない)で完結させなければならない。
- **FR-008**: システムは、「自動」設定時は既存のシステム設定(OS/ブラウザの配色設定)への追従動作を維持し、「ライト固定」「ダーク固定」設定時はシステム設定の変化に関わらず指定テーマを維持しなければならない。
- **FR-009**: システムは、テーマ設定を永続化し、パネルを再度開いた際も直前の設定を維持しなければならない。
- **FR-010**: システムは、一覧に選択モードを開始する操作を提供し、選択モード中は各カードにチェックボックス等の選択UIを表示しなければならない。
- **FR-011**: システムは、選択モード中に選択された項目に対して一括削除操作を提供しなければならない。一括削除は確認操作を経て確定し、確定後は取り消し不可としなければならない。
- **FR-012**: システムは、一括削除完了後、削除された項目のみを一覧・永続化データから除去し、選択されなかった項目には影響を与えてはならない。
- **FR-013**: システムは、タブの切替または検索キーワードの入力が発生した場合、選択モードおよび選択状態を解除しなければならない。
- **FR-013a**: システムは、選択モード中に削除を伴わず選択状態を解除する「キャンセル/選択解除」操作を提供しなければならない。
- **FR-014**: システムは、選択件数が0件の状態では一括削除操作を実行不可(無効化)にしなければならない。

### Key Entities

- **項目（Item）**: req-000001で定義済み。本specでは並び順を表す属性(例: 表示順序値)を新たに保持する。
- **表示設定（Settings）**: req-000003で定義済みの`maskEnabled`に加え、本specではテーマ設定(自動/ライト固定/ダーク固定)を新たに保持する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は、項目の並び替えを1操作(ドラッグ1回、または上下移動ボタン1回のクリック)で完了できる。
- **SC-002**: 並び替え後の順序は、パネルを閉じて再度開いた場合に100%維持される。
- **SC-003**: 利用者は、テーマ設定の変更を1操作で完了でき、変更は即時(200ms以内)に画面へ反映される。
- **SC-004**: テーマ設定は、パネルを閉じて再度開いた場合に100%維持される。
- **SC-005**: 利用者は、複数項目の一括削除を、個別削除を繰り返す場合より少ない操作回数(選択N件+削除操作1回+確認1回)で完了できる。
- **SC-006**: 一括削除操作は、選択した項目の100%を削除し、未選択項目の削除は0件である。

## Assumptions

- 一括削除のチェックボックスは常時表示せず、専用の「選択モード」を開始した場合にのみ各カードに表示する（通常の一覧表示はチェックボックスなしのまま維持する）。
- 項目の並び替えはドラッグ&ドロップを基本とし、ドラッグ操作が難しい場合の代替手段として、カードのケバブメニューに「上へ移動」「下へ移動」も用意する。
- 「選択モード」は一覧上部または各カードに配置する専用の開始操作(例: ヘッダーの「その他メニュー」からの「選択」)で開始する。具体的なUI配置は計画・実装フェーズで具体化する。
- 並び順のデータ保持方法(項目データへの順序フィールド追加等)は、既存の`items`ストレージ構造を拡張する形とし、既存フィールドの意味・バリデーションは変更しない。
- テーマ設定の保存先は、既存の`settings`ストレージ(マスク設定と同じキー)を拡張する形とする。
- 一括削除の確認ダイアログの具体的な見た目(ブラウザ標準の確認ダイアログか、パネル内の独自確認UIか)は計画・実装フェーズで具体化する。いずれの場合も「確認操作を経てから確定する」という要件は満たす。
- 既存spec `002-side-panel-ui` で実装済みのタブ+カード一覧、インライン登録編集、マスク切替、検索、システム設定への自動テーマ追従は変更せず、本specの機能はその上に追加される。
- 「登録順」「名前順」等のソート基準切替機能は本specのスコープ外とする(手動並び替えのみを対象とする)。将来必要になった場合は別途Reqordで要件化する。
