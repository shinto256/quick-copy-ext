# Quickstart: サイドパネルのキーボード操作対応の検証手順

## 前提

- Google Chrome（またはEdge）114以降。
- リポジトリを取得済み、`npm install` 実行済み。
- 本feature実装後の状態。`chrome://extensions` で拡張機能を読み込み・再読み込み済み。
- 検証用データとして**グループを5個以上**登録し、各グループに項目が数件ずつ登録されていること。
- **本セクション1〜3はマウスに触らずに実施する**（キーボードだけで完了できることが検証対象）。
  拡張機能アイコンのクリックだけはマウスで行ってよい。

---

## 1. キーボードでグループを切り替える（User Story 1 / SC-001, SC-003, SC-007）

1. サイドパネルを開き、`Tab` を押してフォーカスを進める → 検索欄・マスク切替・項目追加ボタン・
   その他メニュー・各タブを経て、**タブバー末尾のパネルを開くボタン**にフォーカスが当たることを確認する。
   各要素でフォーカス位置が黄色と黒の二重リングで判別できること。
2. そのボタンで `Enter` を押す → 全グループパネルが開き、絞り込み入力にフォーカスが当たることを
   確認する。
3. `Tab` を押す → **縦リストの最初の行にフォーカスが移り、フォーカスリングが表示される**ことを
   確認する（FR-001 / FR-002）。リングの見た目が手順1で見たボタンと同じであること（SC-007）。
4. `Tab` を押し続ける → **行 → その行の三点リーダー → 次の行 → その三点リーダー**の順に進み、
   飛ばされる行がないことを確認する（FR-004 / FR-005）。未分類の行には三点リーダーがないため、
   未分類の次は次の行に進むこと。
5. 任意の行にフォーカスを合わせ `Enter` を押す → そのグループへ切り替わり、パネルが閉じることを
   確認する（FR-003）。
6. 再度パネルを開き、行にフォーカスして `Space` を押す → 同じくグループが切り替わり、
   **ページがスクロールしない**ことを確認する（FR-003）。
7. 再度パネルを開き、絞り込み入力に一致しない文字列を入力してから `Tab` を押す →
   縦リストにフォーカス可能な行がなく、フォーカスが次の操作要素（グループを追加）へ進むことを
   確認する（FR-005 の対象が0件のケース）。
8. **ここでマウスを使う**: 縦リストの行をポインタで押す → グループが切り替わることを確認する
   （FR-006。行をフォーカス可能にしてもポインタ操作の挙動が変わっていないこと）。

## 2. キーボードでグループを並び替える（User Story 2 / SC-002, SC-004）

1. パネルを開き、`Tab` で**縦リストの最下部の行**にフォーカスを合わせる。
2. `Alt` + `↑` を押す → その行が1つ上へ移動し、**フォーカスが移動した行に残っている**ことを
   確認する（FR-007 / FR-009）。
3. `Alt` + `↑` を押し続ける → **先頭まで移動できる**ことを確認する。この間マウスに触らないこと
   （SC-002）。
4. `Alt` + `↓` を押す → 1つ下へ戻ることを確認する（FR-007）。
5. **先頭の行**にフォーカスして `Alt` + `↑` を押す → 順序が変わらず、エラーも表示されないことを
   確認する（FR-011）。
6. **末尾の行**にフォーカスして `Alt` + `↓` を押す → 同様に何も起こらないことを確認する（FR-011）。
7. **未分類の行**にフォーカスして `Alt` + `↑` / `Alt` + `↓` を押す → 未分類も移動することを
   確認する（FR-010）。
8. `Escape` でパネルを閉じ、タブバーを確認する → タブの表示順が並び替え後の順序と一致していることを
   確認する（FR-015）。
9. サイドパネルを閉じて開き直す → 並び替えた順序が保持されていることを確認する（FR-008）。
10. パネルを開き、絞り込み入力に文字列を入力してから `Tab` で行にフォーカスし `Alt` + `↑` を押す →
    **並び替えが行われない**ことを確認する（FR-012 / SC-004）。
11. 行の三点リーダーから「名称を変更」を選んでインライン編集にし、`Tab` で他の行にフォーカスして
    `Alt` + `↑` を押す → **並び替えが行われない**ことを確認する（FR-013 / SC-004）。
12. インライン編集の入力欄にフォーカスがある状態で `Alt` + `↑` を押す → 並び替えは起こらず、
    入力欄の通常の操作が妨げられないことを確認する（FR-014）。
13. 同じ入力欄で `Enter` を押す → 名称変更が確定し、パネルは閉じないことを確認する
    （既存挙動の維持）。
14. 保存失敗時の挙動（FR-016）は通常操作では再現できない。`chrome://extensions` の
    Service Worker コンソールから `chrome.storage.local.set` で `groups` を書き換えて
    `reorderTabs` の検証を失敗させ、エラー表示が出たうえで保存済みの順序から再描画され、
    **操作していた行にフォーカスが戻る**ことを確認する。

## 3. オーバーレイのフォーカス管理（User Story 3 / SC-005, SC-006）

### 全グループパネル

1. `Tab` でタブバー末尾のボタンにフォーカスし、`Enter` でパネルを開く。
2. `Tab` を繰り返し押す → 絞り込み入力・閉じるボタン・各行・各三点リーダー・グループを追加を
   一巡した後、**最初の要素に戻る**ことを確認する。背後のタブバーや項目一覧へフォーカスが
   移らないこと（FR-017 / SC-005）。
3. `Shift` + `Tab` を繰り返し押す → 逆順に一巡して**最後の要素に戻る**ことを確認する（FR-017）。
4. `Escape` を押す → パネルが閉じ、**フォーカスがタブバー末尾のボタンへ戻る**ことを確認する
   （FR-018 / SC-006）。
5. 再度開いて閉じるボタン（`Tab` で移動して `Enter`）で閉じる → 同様にフォーカスが戻ることを
   確認する（FR-018）。
6. 行にフォーカスした状態で三点リーダーから「削除」を選び、確認を承諾してグループを削除する →
   削除後にパネルを閉じたとき、**フォーカスがタブバー末尾のボタンへ戻る**ことを確認する
   （FR-019。記憶していた行が失われているケース）。
7. 行メニューを開いた状態で `Escape` を押す → メニューだけが閉じ、パネルは閉じないことを確認する
   （既存挙動の維持）。
8. インライン編集中に `Escape` を押す → 編集が取消されるだけでパネルは閉じず、
   **フォーカスがその行に残る**ことを確認する（FR-021）。

### 項目登録フォーム

9. `Tab` で項目追加ボタン（`＋`）にフォーカスし、`Enter` でフォームを開く → 名前欄にフォーカスが
   当たることを確認する。
10. `Tab` を繰り返し押す → 名前・値・グループ選択・保存・キャンセルを一巡した後、
    **最初の要素に戻る**ことを確認する。背後の要素へフォーカスが移らないこと（FR-017 / SC-005）。
11. `Shift` + `Tab` でも同様に循環することを確認する（FR-017）。
12. 名前と値を入力してから `Escape` を押す → **フォームが閉じ、入力内容は保存されず**、
    フォーカスが項目追加ボタンへ戻ることを確認する（FR-020 / FR-018）。
13. 一覧を確認する → 手順12で入力した項目が登録されていないことを確認する（FR-020）。
14. 既存項目の三点リーダーから「編集」でフォームを開き、`Escape` で閉じる → 変更が保存されず、
    フォーカスが妥当な位置へ戻ることを確認する。

## 4. 既存機能の回帰確認（SC-008）

**この節はマウスを使って実施する。** 本featureでポインタ操作を壊していないことが検証対象。

1. 縦リストの行をポインタで押す → グループが切り替わり、パネルが閉じる。
2. 縦リストの行を掴んで動かす → 移動先の行が退避し、離すと並び替えが確定する。
3. 行を押してほとんど動かさずに離す → 並び替えではなくグループ切替になる（5px閾値の判定）。
4. 行の三点リーダーをポインタで押す → 並び替えもグループ切替も起こらず、メニューが開く。
5. 絞り込み中に行を掴む → 並び替えが始まらないが、押して離せば切替はできる。
6. 項目カードを掴んで動かす → 項目の並び替えが動作する。値の長さが違うカードでもずれない。
7. 項目カードを押してほとんど動かさずに離す → 値がコピーされる。
8. 項目カードの `▲▼` で並び替えができる。
9. 項目の登録・編集・削除、マスク表示切替、項目名検索、選択モードによる一括削除・一括グループ変更、
   テーマ切替が従来どおり動作する。

## 5. 自動テストの実行

```bash
npm test
```

- 既存テストがすべてパスすること（回帰なし）。本featureは storage層を変更しないため、
  既存のテストに影響は出ない見込み。
- 新規: `tests/unit/listReorder.test.js` の `moveInList` のテスト
  （[contracts/list-reorder-contract.md](./contracts/list-reorder-contract.md) 参照）がパスすること。
  特に**先頭で上へ、末尾で下へ移動しても順序が変わらない**こと（FR-011）を含む。

`src/sidepanel/focusTrap.js` と `groupPanel.js` / `sidepanel.js` の変更分はDOM操作が中心のため、
既存specと同方針でユニットテスト対象外とし、上記1〜4の手動検証で担保する。
