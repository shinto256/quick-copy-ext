# Contract: listReorder 並び順の組み替え（新規）

対象: `src/sidepanel/listReorder.js`（新規ファイル）

配列の要素を1つ上・1つ下へ移動するだけの純関数。DOMにも `chrome` API にも依存しない。
境界での無変更（spec FR-011）を自動テストで担保するために切り出す。

## エクスポート

```text
moveInList(list: T[], index: number, offset: number): T[]
```

---

## moveInList(list, index, offset)

### 振る舞い

1. `index + offset` が `[0, list.length - 1]` の範囲外なら、`list` の**内容が同じ新しい配列**を返す
   （順序は変更しない）。
2. `index` が `[0, list.length - 1]` の範囲外なら、同様に内容が同じ新しい配列を返す。
3. それ以外は、`index` の要素を取り除き `index + offset` の位置へ挿入した新しい配列を返す。
4. 引数の `list` は変更しない（非破壊）。

### 戻り値の性質（事後条件）

- 常に新しい配列を返す（引数と同一の参照は返さない）
- 要素数は `list.length` と同じ
- 要素の集合は `list` と同じ（要素の増減・置換は起きない）

### エラー

投げない。範囲外の入力は上記のルールで吸収する。

### テスト観点

- 中央の要素を `offset = -1` で移動すると1つ前へ入れ替わる。
- 中央の要素を `offset = 1` で移動すると1つ後ろへ入れ替わる。
- **先頭の要素を `offset = -1` で移動しても順序が変わらない**（spec FR-011）。
- **末尾の要素を `offset = 1` で移動しても順序が変わらない**（spec FR-011）。
- 要素が1件の配列に対してどちらの `offset` でも順序が変わらない。
- 空配列に対して順序が変わらず、エラーにならない。
- `index` が負、または `list.length` 以上のとき順序が変わらない。
- 引数の配列が変更されない（呼び出し前後で同一内容）。
- 戻り値が引数と別の配列インスタンスである。
- `offset` が `±2` 以上でも、範囲内なら指定位置へ移動する（将来「先頭へ移動」等を足す余地）。
- 要素数51（グループ上限50 + 未分類1）の配列で末尾から先頭まで `offset = -1` を50回適用すると、
  対象要素が先頭に来る。
