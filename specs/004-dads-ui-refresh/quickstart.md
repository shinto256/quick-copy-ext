# Quickstart: DADS準拠UIデザイン刷新の検証

**Feature**: 004-dads-ui-refresh | **Date**: 2026-09-02

実装が spec の成功基準を満たすことを確認する手順。

## 前提

- Node.js (既存の開発環境と同じ)
- Chrome または Edge (最新版)
- リポジトリのクローンと `npm install` 済み

## 1. 自動テスト

```bash
npm test
```

**期待結果**: 全テストが成功する。内訳は以下。

| テスト | 検証内容 | 対応 |
|---|---|---|
| `contrastRatio.test.js` | `sidepanel.css` の色トークンから、[contracts/design-tokens.md](./contracts/design-tokens.md) の検査ペア19組をライト/ダーク両テーマで検証 | SC-001, FR-025 |
| `groupRepository.test.js` ほか既存5件 | 既存のデータ層ロジック(変更なし) | SC-004(補助) |

コントラスト比テストが失敗する場合、出力に「どのペアが何倍で基準に何倍足りないか」が示される。トークンの値をDADSプリミティブスケール上の別の段階に差し替えて再実行する。

## 2. 拡張機能の読み込み

1. Chrome で `chrome://extensions` を開く
2. 「デベロッパーモード」を有効にする
3. 「パッケージ化されていない拡張機能を読み込む」でリポジトリのルートを選択する
4. ツールバーの拡張機能アイコンからサイドパネルを開く

## 3. 文字サイズと行間の確認 (SC-002)

サイドパネルを右クリック →「検証」でDevToolsを開き、Consoleで実行する。

```js
[...document.querySelectorAll('body *')]
  .filter(el => el.textContent.trim() && !el.children.length)
  .map(el => {
    const s = getComputedStyle(el);
    return { sel: el.className || el.tagName, size: s.fontSize, lh: s.lineHeight };
  })
  .filter(x => parseFloat(x.size) < 14);
```

**期待結果**: 空配列。14px未満のテキストが存在しない。

本文相当(`.item-value`)の行間確認:

```js
const el = document.querySelector('.item-value');
const s = getComputedStyle(el);
parseFloat(s.lineHeight) / parseFloat(s.fontSize);   // >= 1.5 であること
```

## 4. キーボード到達性とフォーカス表示の確認 (SC-003)

項目を3件以上、グループを2つ以上登録した状態で行う。

1. サイドパネル内をクリックしてフォーカスを移す
2. Tab キーを繰り返し押し、以下すべてに到達し、各所でフォーカス表示(黒枠+黄色の帯)が見えることを確認する
   - 検索入力欄
   - マスク解除チェックボックス
   - 項目追加ボタン
   - その他メニューボタン
   - 各グループタブ
   - タブ追加ボタン
   - 各項目の並び替えボタン(▲▼)
   - 各項目のコピーボタン
   - 各項目のケバブボタン
3. Enter / Space で各操作が実行できることを確認する
4. その他メニューを開き、メニュー項目へ Tab で到達できることを確認する
5. 「選択」モードに入り、各項目のチェックボックス、削除ボタン、キャンセルボタンへ到達できることを確認する

**期待結果**: すべての要素に到達でき、いずれもフォーカス表示が視認できる。マウスクリック時にはフォーカス表示が出ない(`:focus-visible` の挙動)。

## 5. テーマ切替の確認 (SC-001)

1. その他メニュー →「テーマ」→「ライト」を選択。配色がライトになることを確認
2. 同様に「ダーク」を選択。配色がダークになることを確認
3. 「自動」を選択し、OSのテーマ設定に追従することを確認
4. 各テーマでフォーカス表示(Tab キー)が背景に埋もれず視認できることを確認

**期待結果**: 3つのテーマすべてで文字が読め、フォーカス表示が判別できる。

## 6. 書体の確認 (SC-007)

DevTools の Network タブを開いた状態でサイドパネルを再読み込みし、`NotoSansJP-subset.woff2` が読み込まれることを確認する。

```js
document.fonts.check('16px "Noto Sans JP"');   // true であること
```

ファイルサイズの確認:

```bash
ls -l src/sidepanel/fonts/NotoSansJP-subset.woff2
```

**期待結果**: 1MB(1,048,576バイト)以下。

収録外文字のフォールバック確認: 項目名に常用漢字外の文字(例: `髙`、`﨑`)を含む項目を登録し、字面が異なっても表示が崩れないことを確認する。

## 7. 最小幅表示の確認 (SC-006)

サイドパネルの境界をドラッグして最小幅まで狭める。

**期待結果**:
- 横方向のスクロールバーが本文領域に出ない(タブ列の横スクロールは意図した挙動)
- 要素同士が重ならない
- 文字サイズが14px以上を保つ(手順3を最小幅で再実行して確認)

## 8. 既存機能の回帰確認 (SC-004, SC-005)

[checklists/regression.md](./checklists/regression.md) の全項目を実施する。

**期待結果**: 全項目が合格。特に、目的の項目をコピーするまでの操作回数が刷新前と同じであること(SC-005)。
