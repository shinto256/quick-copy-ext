# Feature Specification: DADS準拠UIデザイン刷新

**Feature Branch**: `feature/req-000008`

**Created**: 2026-09-02

**Status**: Draft

**Reqord Requirement**: req-000008 「DADS準拠UIデザイン刷新」 (status: approved, v1.0, priority: medium)

**Input**: サイドパネルUIの視覚デザインを、デジタル庁デザインシステム(DADS)の基本デザイン(Foundations)に準拠させる。カラー、タイポグラフィ、レイアウト、余白、角の形状、エレベーションを DADS の体系に合わせて再定義し、アクセシビリティ基準(JIS X 8341-3:2016 / WCAG 2.2)を満たす。既存機能(req-000001〜req-000007)の挙動・データ仕様は変更せず、見た目の刷新に限定する。

## Clarifications

### Session 2026-09-02

- Q: 文字サイズ14px下限の適用範囲は? (補助ラベルに例外を認めるか) → A: 例外を設けず全テキストを14px以上に統一する。1画面あたりの表示項目数が現行の約10件から約8件に減ることを許容する
- Q: DADS指定書体を拡張機能に同梱するか、端末の書体で代替するか? → A: 常用漢字・かな・英数に絞ったサブセットを同梱する。収録外の文字(異体字・旧字等)は代替書体にフォールバックする
- Q: コントラスト比4.5:1以上(SC-001)を満たすことを何によって確認するか? → A: 自動テストで検証する。定義済みの色の値から前景と背景の全組み合わせのコントラスト比を算出し、ライト/ダーク両テーマで基準を満たすことを検査する
- Q: 既存機能が刷新後も壊れていないことをどう確認するか? → A: 手動確認チェックリストを整備し、実装後に全既存機能を実際に操作して確認する。既存の自動テストはデータの読み書きのみを対象としており見た目の変更では失敗しないため、これ単独では回帰確認の根拠にしない

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 統一された配色と書体で読みやすく使える (Priority: P1)

利用者がサイドパネルを開くと、公的機関の基準に沿った配色と書体で項目一覧が表示される。文字は小さすぎず、行間にゆとりがあり、項目名と値、ボタンやタブの役割が色と濃淡で明確に区別できる。ライトテーマでもダークテーマでも、文字が背景に埋もれることなく読める。

**Why this priority**: 読みやすさは全ユーザーが最初に体感する価値であり、コントラスト不足や小さな文字は利用そのものを妨げる。これ単体を実装しても「読みやすくなった」という価値が独立して届く。

**Independent Test**: ライト/ダーク両テーマでサイドパネルを開き、全テキスト要素の文字サイズ・行間・前景背景のコントラスト比を計測することで単独検証できる。他のストーリーの実装を待たずに検証可能。

**Acceptance Scenarios**:

1. **Given** 利用者がライトテーマでサイドパネルを開いた状態, **When** 項目一覧・タブ・ボタン・入力欄を確認する, **Then** すべてのテキストが背景に対しコントラスト比4.5:1以上で表示され、境界線・アイコン・状態表示は3:1以上である
2. **Given** 利用者がテーマをダークに切り替えた状態, **When** 同じ画面要素を確認する, **Then** ライトテーマと同じコントラスト比の基準を満たす
3. **Given** 利用者がサイドパネルを開いた状態, **When** 表示されている任意のテキストを確認する, **Then** 文字サイズは14px以上であり、本文相当のテキストは行間が文字サイズの1.5倍以上である
4. **Given** 指定書体が利用できない環境, **When** サイドパネルを開く, **Then** 代替書体で表示され、文字の重なり・見切れ・レイアウト崩れが発生しない

---

### User Story 2 - キーボードだけで操作でき、現在位置が常に分かる (Priority: P2)

キーボードやスクリーンリーダーを使う利用者が、マウスを使わずに検索・タブ切替・コピー・編集・削除の各操作へ到達できる。移動のたびに、いまどの要素にいるかが明確な枠線で示され、背景色に埋もれない。

**Why this priority**: アクセシビリティ基準の中核であり、マウスを使えない利用者には必須。ただし配色・書体の土台(P1)が整ってから重ねる方が、フォーカス表示の視認性を正しく検証できる。

**Independent Test**: Tabキーのみで全インタラクティブ要素を巡回し、各要素でフォーカス表示が視認できるかを確認することで単独検証できる。

**Acceptance Scenarios**:

1. **Given** 利用者がサイドパネルを開いた状態, **When** Tabキーで順に移動する, **Then** ボタン・入力欄・タブ・チェックボックス・メニュー項目・並び替えボタンのすべてでフォーカス表示が視認できる
2. **Given** 利用者がダークテーマで操作している状態, **When** Tabキーで要素を移動する, **Then** フォーカス表示が背景に埋もれず、明確に判別できる
3. **Given** 利用者が現在選択中のグループタブを確認したい状態, **When** タブ列を見る, **Then** 選択中のタブが色と文字の太さの両方で区別でき、色の違いだけに依存しない

---

### User Story 3 - 余白と階層が整い、情報のまとまりが掴める (Priority: P3)

利用者が一覧を見たとき、項目カード・ヘッダー・タブ列・選択ツールバーといった情報のまとまりが、一貫した余白と角の形状、影の階層によって視覚的に区切られている。ポップアップメニューや登録フォームは、背後の一覧より手前にあることが影で伝わる。

**Why this priority**: 情報構造の把握を助けるが、可読性(P1)や操作到達性(P2)に比べると欠けても利用は成立する。最後に整えることで全体の完成度が上がる。

**Independent Test**: 各コンポーネントの余白・角丸・影が定義済みスケールのいずれかの値のみを使っているかを確認することで単独検証できる。

**Acceptance Scenarios**:

1. **Given** 利用者が項目一覧を表示している状態, **When** 画面内の余白を確認する, **Then** 要素間の余白が一貫したスケール上の値で構成されている
2. **Given** 利用者がメニューまたは登録フォームを開いた状態, **When** 背後の一覧との関係を見る, **Then** 影による階層表現で手前に浮いていることが判別できる
3. **Given** サイドパネルの幅を最小まで狭めた状態, **When** 一覧・ヘッダー・タブ列を確認する, **Then** 文字サイズ14px以上と余白が維持され、要素の重なり・横方向のはみ出しが発生しない

---

### Edge Cases

- 収録書体に含まれない文字(異体字・旧字体・記号)を含む項目名や値を登録したとき、代替書体との混在で文字幅や高さが不揃いになってもレイアウトが崩れないか
- 収録書体の読み込みが完了する前に画面が表示されたとき、文字が一瞬消える・大きく位置がずれるといった現象が起きないか
- ダークテーマでフォーカス表示が背景と同系色になり判別できなくなることがないか
- サイドパネル最小幅で、長い項目名や長い値がはみ出さず折り返されるか
- マスク表示中の値(伏せ字)でも、通常テキストと同じコントラスト基準を満たすか
- 項目が0件の空状態、および多数件で縦スクロールが発生した状態でも余白と階層が崩れないか
- 先頭の項目で「上へ移動」、末尾の項目で「下へ移動」を押したときに、順序が変わらずエラーにもならないか
- コピー成功メッセージやエラーメッセージが、色だけでなく文言でも成否を伝えているか

## Requirements *(mandatory)*

### Functional Requirements

#### 配色

- **FR-001**: システムは、UI全体の色をDADSの基本デザインに定義された配色体系に基づいて表示しなければならない。本UIで用いるのは主要色・背景色・グレースケール・セマンティックカラーであり、副次色・第三色は使用しない
- **FR-002**: システムは、すべてのテキストとその背景の間でコントラスト比4.5:1以上を確保しなければならない
- **FR-003**: システムは、境界線・アイコン・状態表示などテキスト以外の識別要素について、背景とのコントラスト比3:1以上を確保しなければならない
- **FR-004**: システムは、成功・エラー・警告の状態表示にDADSのセマンティックカラー(成功=緑系、エラー=赤系、警告=黄またはオレンジ系)を用いなければならない
- **FR-005**: システムは、状態表示の成否を色のみで伝えてはならず、文言または記号を併用しなければならない
- **FR-006**: システムは、ライトテーマとダークテーマの双方について配色を定義し、いずれのテーマでもFR-002およびFR-003の基準を満たさなければならない
- **FR-007**: 利用者は、既存のテーマ切替操作(自動/ライト/ダーク)をこれまでと同じ手順で行えなければならない

#### 書体

- **FR-008**: システムは、本文および UI テキストにDADS指定のサンセリフ書体を用い、モノスペース表示が必要な箇所にはDADS指定のモノスペース書体を用いなければならない。指定書体は端末環境に依存せず表示できるよう、拡張機能自体に収録しなければならない
- **FR-009**: システムは、収録書体に含まれない文字(異体字・旧字体など)、および収録書体を読み込めなかった場合に、代替書体を用いて表示し、文字の欠落やレイアウトの崩れを発生させてはならない
- **FR-024**: システムは、書体の収録による配布パッケージの増加を1MB以内に抑えなければならない
- **FR-010**: システムは、すべてのテキストを14px以上の文字サイズで表示しなければならない。補助ラベル・状態メッセージ・小型ボタンを含め、例外は認めない
- **FR-011**: システムは、文字の太さを標準(400)と太字(700)の2段階のみで表現しなければならない
- **FR-012**: システムは、本文相当のテキストの行間を文字サイズの1.5倍以上とし、単一行で完結するUI要素については1.0〜1.3倍の範囲を許容する

#### 余白・角の形状・階層

- **FR-013**: システムは、要素間の余白を一貫したスケール上の値のみで構成しなければならない
- **FR-014**: システムは、角の丸みをコンポーネント種別ごとに統一した値で表示しなければならない
- **FR-015**: システムは、重なり合う要素(ポップアップメニュー・登録フォーム)の前後関係を影による階層表現で示さなければならない

#### アクセシビリティ

- **FR-016**: システムは、すべてのインタラクティブ要素(ボタン、入力欄、タブ、チェックボックス、メニュー項目、並び替えボタン)にフォーカス表示を提供しなければならない
- **FR-017**: システムは、フォーカス表示をDADSが定めるフォーカス表現(明色と黒の二重構造)で行い、独自の色に置き換えてはならない
- **FR-018**: 利用者は、キーボード操作のみで検索・タブ切替・項目のコピー・編集・削除・並び替え・一括削除の各操作に到達できなければならない
- **FR-019**: システムは、選択中のグループタブを色以外の手掛かり(文字の太さまたは記号)でも区別できるように表示しなければならない
- **FR-020**: システムは、JIS X 8341-3:2016 および WCAG 2.2 の適合レベルAAに相当する達成基準を満たさなければならない
- **FR-025**: 開発者は、定義済みの色の値から前景と背景の全組み合わせのコントラスト比を自動で検査でき、基準(テキスト4.5:1、テキスト以外3:1)を下回る組み合わせが存在する場合に検査が失敗しなければならない

#### 互換性

- **FR-021**: システムは、既存の登録・一覧表示・コピー・マスク表示切替・グループ管理・並び替え・テーマ切替・一括削除の各機能について、刷新前と同一の操作手順と結果を維持しなければならない
- **FR-026**: 開発者は、既存機能が刷新前と同一に動作することを確認するための手動確認チェックリストを参照でき、チェックリストは上記全機能の操作手順と期待結果を網羅していなければならない
- **FR-022**: システムは、保存済みの登録データを刷新の前後で変換や移行なしにそのまま表示できなければならない
- **FR-023**: システムは、サイドパネルが取り得る最小幅においてもFR-010の文字サイズとFR-013の余白を維持し、要素の重なりや横方向のはみ出しを発生させてはならない

### Key Entities

- **デザイントークン**: 色・文字サイズ・行間・余白・角の丸み・影の各値に名前を与えた定義の集合。テーマ(ライト/ダーク)ごとに値を持ち、画面の各要素はこの名前を参照して表示される
- **テーマ設定**: 利用者が選択した表示テーマ(自動/ライト/ダーク)。既存機能で保存済みの設定をそのまま利用する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ライトテーマ・ダークテーマの双方において、画面内の全テキストが背景に対しコントラスト比4.5:1以上、テキスト以外の識別要素が3:1以上を満たす(該当箇所100%)。自動検査で全ての前景背景ペアが合格することで確認する
- **SC-002**: 画面内の全テキストの文字サイズが14px以上であり、本文相当テキストの行間が文字サイズの1.5倍以上である(該当箇所100%)
- **SC-003**: キーボード操作のみで全インタラクティブ要素に到達でき、到達した全要素でフォーカス表示が視認できる(該当要素100%)
- **SC-004**: 既存機能(項目登録、一覧表示、コピー、マスク表示切替、グループ管理、並び替え、テーマ切替、一括削除)の操作手順と結果が刷新前と同一である。手動確認チェックリストの全項目が合格し、かつ既存の自動テストが全件成功することで確認する
- **SC-005**: 利用者は刷新前と同じ手順・同じ回数の操作で、目的の項目をコピーできる(操作ステップ数の増加なし)
- **SC-006**: サイドパネルの最小幅表示において、要素の重なりおよび横方向のはみ出しが発生しない(0件)
- **SC-007**: 書体の収録による配布パッケージの増加が1MB以内に収まり、収録範囲(常用漢字・かな・英数)の文字が指定書体で表示される

## Assumptions

- 対象は既存のサイドパネル画面全体であり、拡張機能のアイコンやストア掲載用画像などの制作物は対象外とする
- DADSの基本デザイン(Foundations)のうち、カラー・タイポグラフィ・レイアウト・余白・角の形状・エレベーション・アクセシビリティを対象とする。DADSのコンポーネントライブラリをそのまま導入することは対象外とし、既存の画面構成を保ったまま各基本要素の値を準拠させる
- DADSはウェブサイト向けの基準であり、ブラウザ拡張のサイドパネルという狭幅の表示領域に対しては、文字サイズ下限(14px)とコントラスト比の基準を厳守した上で、余白・文字サイズの選択は狭幅向けに小さめの段階を採る
- DADSのキーカラー体系のうち副次色・第三色は用いない。サイドパネルは単一の主要アクション(コピー)を中心とした狭幅UIであり、色相を増やすと選択状態とアクションの区別がかえって曖昧になるため、主要色1色 + グレースケール + セマンティックカラーで構成する
- 文字サイズを14px以上に統一した結果、1画面あたりの表示項目数が現行の約10件から約8件程度に減少することを許容する。これは可読性とアクセシビリティを情報密度より優先する判断による
- 表示言語は日本語のみを前提とする(多言語対応は対象外)
- 既存のテーマ手動切替機能(req-000006)の保存形式と切替操作をそのまま利用し、テーマ設定の仕様変更は行わない
- 既存の画面構成・操作手順・保存データ形式は変更しない。変更は表示に関わる定義と、キーボード操作および支援技術向けの補助情報の追加に限定する
- 既存の自動テストはデータの読み書きと絞り込みのみを対象としており、表示に関わる変更では失敗しない。したがって既存機能の回帰確認は手動確認チェックリストで担保し、既存テストの成功は補助的な確認と位置づける
- コントラスト比の検証は、定義済みの色の値を入力とする自動検査で行う。画面をレンダリングして検査する方式(ブラウザ上でのアクセシビリティ検査ツールの実行)は対象外とし、色の定義レベルでの検査で担保する
- 自動検査の対象は、実際に画面上で組み合わせて用いられる前景色と背景色のペアに限る。定義上あり得ても画面に現れない組み合わせは検査対象外とする

## Dependencies

- Reqord要件 req-000008 (approved) に紐づく。要件の変更が生じた場合はReqord側の更新を先行させる
- 既存要件 req-000001〜req-000007 の実装が対象画面に存在していることを前提とする(挙動の維持が本仕様の成功基準に含まれる)
- 参照基準: デジタル庁デザインシステム 基本デザイン (https://design.digital.go.jp/dads/foundations/)、JIS X 8341-3:2016、WCAG 2.2
