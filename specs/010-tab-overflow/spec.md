# Feature Specification: タブバーの横スクロール廃止と幅追従表示

**Feature Branch**: `feature/req-000014`

**Created**: 2026-09-04

**Status**: Draft

**Reqord Requirements**: [[req-000014]] タブバーの横スクロール廃止と幅追従表示（承認済み・要約は下記「Reqord要件要約」参照）

**Input**: User description: "req-000014「タブバーの横スクロール廃止と幅追従表示」に基づく仕様作成。概要: グループのタブバーは幅に収まらないと横スクロールになり、狭いサイドパネルではスクロールバーが常に見えて縦方向の領域を占める。横スクロールを廃止し、幅に収まらないタブは表示しない。サイドパネルの幅を広げて余白ができたら収まるタブを表示する。選択中のタブは必ず表示する。"

## Reqord要件要約

- **req-000014（タブバーの横スクロール廃止と幅追従表示）**: グループのタブバーは、タブが幅に収まらないと横スクロールになる。狭いサイドパネルではスクロールバーが常に見える状態になり、限られた縦方向の領域を占め、見た目も落ち着かない。またタブを横スクロールして探す操作は、全グループパネル（[[req-000010]]）で一覧と絞り込みができるようになった今では役目が薄い。タブバーの横スクロールを廃止し、幅に収まらないタブは表示しない。隠れたタブは全グループパネルから到達できるためアクセス手段は失われない。サイドパネルは利用者が幅を変えられるため、幅を広げて余白ができたら収まるタブを表示し、狭めたら収まらないタブを隠す。選択中のタブは並び順の位置にかかわらず必ず表示する。

本specは `006-group-navigation` で実装したタブバーの表示方式を変更する。

**既存specの置き換え**: `006-group-navigation` の以下が置き換わる。

| 置き換わる対象 | 内容 | 本specでの扱い |
| --- | --- | --- |
| spec 006 FR-006 の前提 | グループが上限の50個ある場合も、スクロールによって全件を確認できるようにする（全グループパネル側の要件） | **変更しない。** 全件の確認は全グループパネルの縦リストが担っており、タブバーの横スクロールとは別 |
| spec 006 の「タブバーは横スクロール」という表示方式 | タブが溢れた場合は横スクロールで参照する | 横スクロールを廃止し、収まらないタブを表示しない（本spec FR-001〜FR-004） |

spec 006 FR-001（タブバー末尾のボタンの固定表示）、FR-012（保存された並び順で表示）、FR-024（タブ名の末尾省略）は変更しない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 横スクロールバーが出ない (Priority: P1)

利用者は、グループを増やすとタブバーに横スクロールバーが現れ、狭いサイドパネルの縦方向の領域を奪われている。スクロールバーを出さず、収まらないタブは表示しないでほしい。

**Why this priority**: 本specの目的そのもの。スクロールバーが領域を占めることと、横スクロールで探す操作の両方をなくす。

**Independent Test**: グループを10個以上登録した状態でタブバーを確認し、横スクロールバーが表示されず、タブがタブバーの幅からはみ出していないことを確認する。

**Acceptance Scenarios**:

1. **Given** グループを10個以上登録している、**When** タブバーを確認する、**Then** 横スクロールバーが表示されていない。
2. **Given** タブの合計幅がタブバーの幅を超える、**When** タブバーを確認する、**Then** 幅に収まらないタブは表示されておらず、タブバーからはみ出しているタブもない。
3. **Given** グループが少なくタブが全部収まる、**When** タブバーを確認する、**Then** すべてのタブが表示されており、何も隠れていない。
4. **Given** タブが隠れている、**When** タブバー末尾のボタンを確認する、**Then** ボタンは表示されており、併記されている数は**隠れているタブも含めた全タブ数**である。
5. **Given** タブが隠れている、**When** そのボタンから全グループパネルを開く、**Then** 隠れていたグループも縦リストに表示され、そこから切り替えられる。
6. **Given** タブが隠れている、**When** キーボードでフォーカスを進める、**Then** 隠れているタブにフォーカスが当たらない。

---

### User Story 2 - 幅を広げると収まるタブが出てくる (Priority: P1)

利用者はサイドパネルの幅を変えられる。幅を広げて余白ができたのにタブが表示されないままだと、広げた意味がない。幅に応じて表示されるタブが増減してほしい。

**Why this priority**: User Story 1 で収まらないタブを隠すため、幅が変わったときに再計算しなければ、広げても隠れたままになる。2つは同時に満たす必要があり、いずれもP1とする。

**Independent Test**: タブが隠れている状態からサイドパネルの幅を広げ、収まるようになったタブが表示されることを確認する。狭めると隠れることも確認する。

**Acceptance Scenarios**:

1. **Given** 幅に収まらないタブが隠れている、**When** サイドパネルの幅を広げる、**Then** 収まるようになったタブが表示される。
2. **Given** すべてのタブが表示されている、**When** サイドパネルの幅を狭める、**Then** 収まらなくなったタブが隠れる。横スクロールバーは表示されない。
3. **Given** 幅を変えている最中、**When** タブバーを確認する、**Then** 表示が追従し、はみ出したタブや横スクロールバーが一時的にも現れない。
4. **Given** グループを追加した、**When** タブバーを確認する、**Then** 新しい幅の状況に応じて表示するタブが再計算されている。
5. **Given** グループを削除した、**When** タブバーを確認する、**Then** 空いた幅に収まるタブが表示される。
6. **Given** タブの並び順を変えた、**When** タブバーを確認する、**Then** 新しい並び順の先頭から詰めて表示される。
7. **Given** グループ名を変更してタブの幅が変わった、**When** タブバーを確認する、**Then** 新しい幅に応じて表示するタブが再計算されている。

---

### User Story 3 - いま見ているグループが分かる (Priority: P1)

利用者は、全グループパネルから並び順の後ろにあるグループへ切り替えることがある。そのタブが幅に収まらない位置にあると、タブバーのどこにも選択中の印が出ず、いまどのグループを見ているのか分からなくなる。

**Why this priority**: 選択中のタブが見えないことは、機能が壊れているのと同じ体験になる。User Story 1 の副作用として必ず起きるため、同時に満たす必要がある。

**Independent Test**: 全グループパネルから並び順の後ろにあるグループへ切り替え、そのタブがタブバーに選択中として表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** タブが隠れる状態で、並び順の後ろにあるグループを全グループパネルから選んだ、**When** タブバーを確認する、**Then** そのタブが選択中として表示されている。
2. **Given** 選択中のタブが表示されるために他のタブが隠れた、**When** タブバーを確認する、**Then** 横スクロールバーは表示されず、はみ出しているタブもない。
3. **Given** 選択中のタブが並び順の先頭に近く、そのまま収まる、**When** タブバーを確認する、**Then** 他のタブが余分に隠れていない。
4. **Given** 選択中のタブが表示されている、**When** サイドパネルの幅を狭めていく、**Then** 選択中のタブは最後まで隠れない。
5. **Given** タブが1つも幅に収まらないほど狭い、**When** タブバーを確認する、**Then** 選択中のタブと末尾のボタンのみが表示され、選択中のタブの名前は末尾省略で表示される。

---

### Edge Cases

- タブが1つも幅に収まらない場合、選択中のタブと全グループパネルを開くボタンのみを表示する。選択中のタブは幅に収まらなくても表示し、名前は末尾省略で表示される。
- タブが全部収まる場合は、すべてのタブを表示する。何も隠れない。
- 選択中のタブが並び順の先頭に近く、そのまま収まる場合は、他のタブを余分に隠さない。
- 幅を狭めていく途中で選択中のタブだけが残る状態になっても、選択中のタブは隠さない。
- グループの追加・削除・並び替え・名称変更のあとも、表示するタブを再計算する。
- サイドパネルが表示されていない状態（幅が0）では計算を行わない。表示されたときに計算する。

## Requirements *(mandatory)*

### Functional Requirements

#### 横スクロールの廃止

- **FR-001**: システムは、タブバーに横スクロールを発生させてはならない。横スクロールバーを表示してはならない。
- **FR-002**: システムは、タブの合計幅がタブバーの幅を超える場合、収まらないタブを表示してはならない。
- **FR-003**: システムは、タブをタブバーの幅からはみ出して表示してはならない。
- **FR-004**: システムは、表示するタブを並び順の先頭から詰めて決めなければならない。

#### 常に表示するもの

- **FR-005**: システムは、選択中のタブを、並び順の位置にかかわらず必ず表示しなければならない。収まらない位置にある場合は、他のタブを隠して場所を作らなければならない。
- **FR-006**: システムは、全グループパネルを開くボタンを常に表示しなければならない。タブが1つも収まらない場合も表示しなければならない。
- **FR-007**: システムは、全グループパネルを開くボタンに併記する数を、隠れているタブを含めた全タブ数としなければならない。
- **FR-008**: システムは、選択中のタブがそのまま収まる場合、他のタブを余分に隠してはならない。

#### 幅の変化への追従

- **FR-009**: システムは、タブバーの幅が変わった場合、表示するタブを再計算しなければならない。
- **FR-010**: システムは、幅が広がって余白ができた場合、収まるようになったタブを表示しなければならない。
- **FR-011**: システムは、幅が狭まった場合、収まらなくなったタブを隠さなければならない。
- **FR-012**: システムは、グループの追加・削除・並び替え・名称変更のあとも、表示するタブを再計算しなければならない。

#### 隠れているタブの扱い

- **FR-013**: システムは、隠れているタブをキーボードのフォーカス移動の対象にしてはならない。
- **FR-014**: システムは、隠れているタブへ全グループパネルから到達できる状態を維持しなければならない。

### Key Entities

本specで追加・変更する永続データはない。どのタブを表示するかは画面の幅から都度決まる一時的な状態であり、保存しない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: タブバーに横スクロールバーが表示される事象が0件である。
- **SC-002**: タブが幅に収まらない状態で、タブバーからはみ出して表示されるタブが0件である。
- **SC-003**: サイドパネルの幅を広げて余白ができた場合、収まるようになったタブが表示される。
- **SC-004**: 選択中のタブがタブバーに表示されない事象が0件である。
- **SC-005**: 全グループパネルを開くボタンが表示されない事象が0件である。
- **SC-006**: 隠れているタブにキーボードのフォーカスが当たる事象が0件である。
- **SC-007**: 隠れているタブへ全グループパネルから到達できる割合が100%である。
- **SC-008**: タブが全部収まる幅では、隠れるタブが0件である。

## Assumptions

- 表示するタブの判定はタブの実際の幅を測って行う。グループ名の長さによってタブの幅が変わるため、固定の個数では決められない。計測の具体的な方法と回数の抑え方は計画・実装フェーズで具体化する。
- サイドパネルの幅の変化を検知する仕組みは計画・実装フェーズで具体化する。利用者がサイドパネルの端をドラッグして幅を変える操作に追従できる方式を選ぶ。
- 隠れているタブを表す視覚的な印（「他に何個ある」といった表示）は、全グループパネルを開くボタンに併記している全タブ数が担う（FR-007）。専用の印は追加しない。
- 隠れているタブへの到達手段は全グループパネルのみとする。タブバーに「次へ」「前へ」のような送り操作は追加しない。全グループパネルには一覧と絞り込みがあり（[[req-000010]]）、送り操作より速く目的のグループへ届く。
- タブ名の末尾省略（[[req-000010]] FR-024）は変更しない。タブ1個あたりの幅の上限はそのまま維持し、その幅を前提に何個収まるかを判定する。
- タブの並び順（[[req-000010]] FR-012）とその変更手段は変更しない。よく使うグループを先頭へ移動すれば表示され続けるという関係も変わらない。
- 全グループパネルの縦リストは従来どおり縦スクロールで全件を参照できる。本specはタブバーの横スクロールのみを対象とする。
- 項目一覧・項目カード・選択モード・オーバーレイのフォーカス管理はいずれも変更しない。
