# Feature Specification: サイドパネルUI刷新

**Feature Branch**: `002-side-panel-ui`

**Created**: 2026-08-28

**Status**: Draft

**Reqord Requirements**: [[req-000001]] 項目登録・保存機能 / [[req-000002]] 一覧表示・コピー機能(デフォルトマスク表示) / [[req-000003]] マスク表示切替機能 / [[req-000004]] グループ管理機能（すべて承認済み・要約は下記「Reqord要件要約」参照）

**Input**: User description: "Chrome拡張のUIをサイドパネル形式に変更する。要件req-000001(項目登録・保存)・req-000002(一覧表示・コピー、マスク表示)・req-000003(マスク切替)・req-000004(グループ管理)は承認済みで、既存spec 001-quick-copy-itemsで実装済み。今回は表示形態とUI構造の刷新機能: 1. 表示形態をChrome Side Panel API相当の常駐パネル表示に変更。2. UIをタブ(グループ)+カード形式一覧に刷新。3. 項目追加・グループ管理を別画面(options)に遷移せずパネル内で完結させる。4. 既存storageリポジトリのロジックは流用し、UI層のみ刷新する。"

## Reqord要件要約

- **req-000001（項目登録・保存機能）**: 名前(1〜50文字)・値(1〜2000文字)を入力して項目を保存する機能。保存は端末ローカルに永続化し、一覧へ即時反映。上限500件。編集・削除も含む。
- **req-000002（一覧表示・コピー機能）**: 登録済み項目を一覧表示し、値をワンクリックでクリップボードにコピーする機能。名前は平文表示、値はデフォルトでマスク(●8文字固定)表示。
- **req-000003（マスク表示切替機能）**: 一覧の値表示をマスク⇔平文で一括切替できるトグル機能。切替状態は永続化。
- **req-000004（グループ管理機能）**: 項目をグループ分けし、一覧をグループ単位で絞り込み表示できる機能。グループの作成・名称編集・削除が可能（削除時、所属項目は「未分類」に戻す）。

本specはこれら4要件のビジネスルール（バリデーション・永続化・マスク仕様・グループ仕様）を変更しない。対象は「表示形態（常駐パネル化）」「UI構造（タブ+カード）」「操作フロー（登録・グループ管理を同一画面内で完結）」の刷新であり、既存spec `001-quick-copy-items` の実装済みロジック（storageリポジトリ層）を流用する前提とする。

## Clarifications

### Session 2026-08-28

- Q: マスク表示切替(req-000003のトグル)は新UIのどこに配置するか？ → A: ヘッダーに常時表示のトグルスイッチとして配置する（既存popupと同様、メニューを開く操作を挟まない）。
- Q: タブ(グループ)を切り替えたとき、検索欄に入力済みのキーワードは保持されるか、リセットされるか？ → A: タブ切替時に検索欄をクリアし、絞り込みを解除する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 常駐パネルからワンクリックでコピーする (Priority: P1)

利用者がブラウザ作業中に、都度クリックしてポップアップを開き直すことなく、画面の一部に常駐するパネルから登録済みの文言をコピーしたい。

**Why this priority**: 既存のポップアップ形式は都度開閉が必要で、他のタブやウィンドウを操作しながらの利用に不向き。常駐表示は既存の一覧・コピー・マスク切替機能（req-000002, req-000003）の使い勝手を底上げする、最も価値の高い変更。

**Independent Test**: 拡張機能アイコンを操作してパネルを開き、他のウェブページを閲覧・操作している間もパネルが閉じずに表示され続け、項目のコピー操作が行えることを確認する。

**Acceptance Scenarios**:

1. **Given** 拡張機能をインストール済み、**When** 拡張機能アイコンを操作する、**Then** ブラウザ画面の一部（サイドパネル領域）に一覧UIが表示される。
2. **Given** パネルが開いている状態、**When** 別のタブに切り替える、**Then** パネルは閉じずに表示され続ける。
3. **Given** パネル内に登録済み項目が表示されている、**When** 項目のコピー操作を行う、**Then** 値がクリップボードにコピーされ、成功フィードバックが表示される。
4. **Given** パネルのヘッダーにマスク表示切替トグルが常時表示されている、**When** トグルを1回操作する、**Then** メニュー等を開く追加操作なしに、選択中タブの全項目の値表示がマスク⇔平文に切り替わる。

---

### User Story 2 - タブ切替でグループごとに項目を見る (Priority: P1)

利用者は、用途ごとにグループ分けした項目を、タブを切り替えることで素早く絞り込んで閲覧したい。

**Why this priority**: グループ機能（req-000004）を実際に使いやすくする表示手段。タブ形式は絞り込み操作の手数を最小化し、一覧機能の中心的な操作体験となる。

**Independent Test**: 複数グループに項目を登録した状態でタブを切り替え、各タブに該当グループの項目のみが表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 複数のグループが作成済み、**When** パネルを開く、**Then** グループ名がタブとして一覧の上部に並んで表示される。
2. **Given** タブが複数ある、**When** 任意のタブを選択する、**Then** そのグループに属する項目のみがカード形式で一覧表示される。
3. **Given** タブ一覧の末尾、**When** 新規タブ追加操作を行う、**Then** グループ名入力後に新しいタブ（グループ）が作成され一覧に追加される。
4. **Given** 未分類の項目が存在する、**When** パネルを開く、**Then** 未分類項目を表示するタブが存在する。

---

### User Story 3 - 画面遷移せずにその場で項目を登録・編集する (Priority: P2)

利用者は、新しい項目を登録したり既存項目を編集したりする際、別画面（設定ページ）に移動せず、一覧を見ているパネル内で作業を完結させたい。

**Why this priority**: 別画面遷移は文脈の切り替えコストが高く、頻繁に発生する登録・編集作業の妨げになる。P1の閲覧・コピー体験が確立した上で、登録導線を統合することが次に価値が高い。

**Independent Test**: パネルを開いたまま項目追加操作を行い、名前・値・グループを入力して保存すると、画面遷移なしに一覧へ即座に反映されることを確認する。

**Acceptance Scenarios**:

1. **Given** パネルの一覧画面、**When** 項目追加操作を行う、**Then** パネル内に入力用UI（モーダルまたは展開フォーム）が表示され、別画面への遷移は発生しない。
2. **Given** 入力用UIに名前・値を入力し所属グループを選択、**When** 保存操作を行う、**Then** 入力UIが閉じ、該当グループのタブ内一覧に新しい項目が即時反映される。
3. **Given** 一覧のカードのメニュー操作、**When** 編集を選択する、**Then** パネル内に既存値が入った入力用UIが表示され、画面遷移なしに更新できる。
4. **Given** 一覧のカードのメニュー操作、**When** 削除を選択する、**Then** 確認の上、画面遷移なしに項目が一覧から削除される。
5. **Given** パネルの一覧画面、**When** グループ管理（作成・名称編集・削除）操作を行う、**Then** 画面遷移なしにタブ構成へ反映される。

---

### User Story 4 - 一覧から目的の項目を検索する (Priority: P3)

利用者は、登録項目数が多くなった場合に、名前で検索して目的の項目を素早く見つけたい。

**Why this priority**: 基本の閲覧・登録体験が整った後に効く補助機能。件数が少ないうちは無くても成立するため優先度は最も低い。

**Independent Test**: 複数項目が登録された状態で検索欄にキーワードを入力し、該当する項目のみが一覧に絞り込まれることを確認する。

**Acceptance Scenarios**:

1. **Given** パネル上部に検索欄がある、**When** キーワードを入力する、**Then** 現在表示中のタブ内で名前が一致する項目のみに一覧が絞り込まれる。
2. **Given** 検索キーワードを入力済み、**When** 検索欄を空にする、**Then** 絞り込みが解除され元の一覧表示に戻る。
3. **Given** 検索キーワードを入力済み、**When** 別のタブ（グループ）に切り替える、**Then** 検索欄はクリアされ、絞り込みは解除された状態で切替後のタブの一覧が表示される。

### Edge Cases

- 登録項目が0件のグループタブを開いた場合、一覧に空状態（未登録である旨）を表示する。
- グループ（タブ）が1つも作成されていない場合、「未分類」タブのみが表示される。
- 項目追加・編集の入力用UI表示中にパネルを閉じた場合、未保存の入力内容は破棄される。
- 検索結果が0件の場合、一覧に検索結果なしを示す空状態を表示する。
- 検索キーワード入力中にタブを切り替えた場合、検索欄はクリアされ、切替後のタブは絞り込みなしの全件表示となる。
- グループ削除操作を行った場合、そのグループのタブは一覧から消え、所属していた項目は「未分類」タブに移動する（データは失われない、req-000004準拠）。
- 登録上限（500件）到達時に項目追加を行った場合、入力用UIを開いたまま保存を拒否し上限到達を通知する（req-000001準拠）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、拡張機能の操作（アイコンクリック等）により、ブラウザ画面の一部に常駐するパネルとして一覧UIを表示しなければならない。パネルは他のタブ・ページを操作している間も表示され続けること。
- **FR-002**: システムは、パネル上部にグループをタブとして一覧表示しなければならない。タブには常に「未分類」が含まれる。
- **FR-003**: システムは、選択中のタブに対応するグループの項目のみをカード形式で一覧表示しなければならない。各カードには項目名、値（マスク状態に応じた表示）、コピー操作、および編集・削除を行う操作を含む。
- **FR-004**: システムは、タブ一覧から新規グループを作成する操作を提供しなければならない。作成はパネル内で完結し、画面遷移を伴わない。
- **FR-005**: システムは、項目の新規登録・編集をパネル内の入力用UI（画面遷移を伴わない表示領域）で行えるようにしなければならない。
- **FR-006**: システムは、項目の入力用UIにおいて名前・値・所属グループを入力・選択できるようにしなければならない。
- **FR-007**: システムは、項目保存操作の成功時、入力用UIを閉じ、該当グループのタブ内一覧へ変更を即時反映しなければならない。
- **FR-008**: システムは、グループの名称編集・削除をパネル内で完結させ、画面遷移を伴わないようにしなければならない。
- **FR-009**: システムは、一覧上部に検索欄を提供し、選択中タブ内の項目を名前で絞り込み表示できるようにしなければならない。
- **FR-010**: システムは、既存の項目登録・一覧表示・コピー・マスク切替・グループ管理の各機能（req-000001〜req-000004）が定めるバリデーション・永続化・表示ルールを、UI形態の変更後も維持しなければならない。
- **FR-011**: システムは、従来別画面で提供していた項目登録・グループ管理の導線を廃止し、常駐パネルのUIに一本化しなければならない。
- **FR-012**: システムは、マスク表示切替（req-000003）のトグルをパネルのヘッダーに常時表示し、メニュー等を開く追加操作なしに1操作で切替が完了できるようにしなければならない。
- **FR-013**: システムは、タブ（グループ）を切り替えた際、検索欄のキーワードをクリアし、絞り込みを解除しなければならない。

### Key Entities

- **項目（Item）**: 名前・値・所属グループを持つ登録データ。req-000001で定義済み。本機能ではカードとして一覧表示・パネル内フォームで登録編集される対象。
- **グループ（Group）**: 項目を分類する単位。req-000004で定義済み。本機能ではタブとして表現される対象。
- **表示モード（マスク設定）**: 値表示をマスク/平文のどちらにするかの設定。req-000003で定義済み。本機能では一覧のカード内表示に反映される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は、拡張機能操作から一覧パネル表示までを1操作（1クリック相当）で完了できる。
- **SC-002**: 利用者は、他のタブ・ページを閲覧・操作している間もパネルを開いたままコピー操作を行える（パネルを閉じ直す必要がある操作は0件）。
- **SC-003**: 利用者は、項目の新規登録を、画面遷移0回でパネル内のみで完了できる。
- **SC-004**: 利用者は、グループの作成・編集・削除を、画面遷移0回でパネル内のみで完了できる。
- **SC-005**: 利用者は、グループタブの切替から該当項目一覧の表示までを1操作で完了できる。
- **SC-006**: 検索欄へのキーワード入力から一覧の絞り込み反映までが150ms以内に完了する。

## Assumptions

- 「常駐パネル」とは、ブラウザウィンドウに対して開閉可能な固定領域として表示され、タブ切替や他ページ操作中も表示状態が維持されるUI形態を指す（具体的な実現手段は計画フェーズで検討する）。
- 既存の項目・グループ・設定データ（chrome.storage.local上のデータ）はUI形態変更後もそのまま利用可能であり、データ移行は不要とする。
- 既存spec `001-quick-copy-items` で実装済みのstorage層（保存・取得・バリデーション等のロジック）はそのまま流用し、本specの対象はUI層（表示・操作導線）に限定する。
- 検索対象は項目名のみとし、値本文の全文検索は対象外とする（マスク時に値の内容を検索できてしまうと表示上のマスク意図と矛盾するため）。
- タブ数・グループ数の上限は既存req-000004の上限（最大50個）をそのまま踏襲する。
- 見本UIにあるグループ以外の付随要素（検索アイコン、鉛筆アイコン、その他メニュー等）のうち、既存4要件に対応がないものは、それを実現する機能自体（例: 検索）としてのみ要件化し、装飾的な見た目の詳細は計画・実装フェーズで具体化する。
